# 序章：本書の狙いとAI／LLMセキュリティの全体像

本書は、AI／LLMを組み込んだアプリケーションのセキュリティ脆弱性を、**初級者から専門家まで**段階的に深掘りするための日本語教科書である。バグバウンティ・脆弱性リサーチ・防御設計の実務に耐える密度を目標に、`roadmaps/ai.md`（URL付き学習ロードマップ、Lv1〜Lv9）の各資料を**原典から取得して**章立てに再構成した。

> **本書のスコープ（重要）**
> 本書は**防御・脆弱性理解・正当なセキュリティ教育／バグバウンティ**のための教材である。攻撃技法は「なぜ成立するのか」という仕組みの理解と、それを踏まえた防御設計のために解説している。**実在サービス・本番環境への無許可の検証や、破壊的な手順は記載しない**。特定の演習環境（PortSwigger等のラボ、CTF）を解くための攻略手順（step-by-stepの解答）も本書の目的ではなく、掲載しない。手を動かす際は、必ず自分が所有する、または明示的に許可された環境（無償の学習用ラボ、意図的に脆弱なローカル環境、スコープ内のバグバウンティ対象）でのみ行うこと。

## なぜ「AIセキュリティ」を体系的に学ぶのか

生成AIの普及により、LLMは「入力を受け取り、外部データを読み、ツールを呼び、出力を下流へ渡す」新しい**信頼できない入力源・信頼できない出力先**としてアプリケーションに組み込まれた。ここで実際にバグバウンティで受理される脆弱性の本命は、突飛な新奇現象ではなく、次の4本柱に集約される。

1. **LLMを引き金にした従来型Web脆弱性** — Insecure Output Handling由来のXSS、Markdown画像経由のデータ窃取、LLM出力経由のSSRF／RCE／SQLi。
2. **間接プロンプトインジェクション（IPI）** — 外部データに仕込んだ指示によるデータ窃取・エージェント乗っ取り。
3. **AIエージェント／MCPの過剰権限・tool poisoning** — ツール呼び出しと自律性が生む新しい攻撃面。
4. **AIサプライチェーン** — モデルファイルのpickleデシリアライズRCEとMLOpsツール（MLflow, Ray, LangChain等）の実CVE。

これらはいずれも、**従来型のセキュア設計原則（入力検証・出力エンコーディング・最小権限・信頼境界の明確化）を、LLMという新しい経路に対して一貫して適用できていない**ことに根本原因がある。既存のWeb／デシリアライズの知識を持つ人ほど、この分野で速く成果を出せる。

- 学習は**第1章（全体像と脅威分類）→第2章（プロンプトインジェクション）**で土台を作り、そこから**第3章（従来型Web脆弱性への接続）**という「受理される本命」へ進むのが効率的である。

- 取得できなかった資料は本文中に `⚠️ 未取得の資料` として明示し、**付録B**に一覧化している。
- 付録Aに原典ロードマップの全URL（107件）をレベル別に再掲した。
