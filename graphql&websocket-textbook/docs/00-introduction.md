# 序章：本書の位置づけと読み方

## 本書が扱う範囲

本書は、GraphQL API と WebSocket（および Cross-Site WebSocket Hijacking, CSWSH）のセキュリティを、攻撃者視点で構造を理解し、**防御・検出・安全な検証**に落とし込むための教科書である。土台にあるのは、実在確認済みの二次資料 URL を段階別に配した学習ロードマップであり、本書はその各段を章に対応させて、原典に忠実に日本語で書き起こしたものである。

GraphQL と WebSocket を一冊にまとめたのには理由がある。どちらも「既存の Web セキュリティ知識（BOLA/BFLA・CSRF・各種 injection）の地続き」でありながら、**プロトコル固有の性質が従来の防御の前提を崩す**という共通構造を持つ。GraphQL では単一エンドポイント・introspection・alias・batching・深いネストが、WebSocket では「認証がハンドシェイク時にしか行われない」という性質が、それぞれ WAF・レート制限・アクセス制御・同一オリジンポリシーの想定を裏切る。この「なぜ前提が崩れるのか」を掴むことが、自動スキャナでは見つからない深さに到達する鍵になる。

## 全体マップ（3パート・10章）

- **Part A：GraphQL セキュリティ（第1〜5章）** — 仕組みの攻撃者視点での理解（第1章）、recon と introspection（第2章）、★認可・アクセス制御 BOLA/BFLA（第3章）、★GraphQL 特有の攻撃 alias/batching・ネスト DoS・injection（第4章）、ツールと方法論（第5章）。
- **Part B：WebSocket セキュリティ（第6〜8章）** — ハンドシェイクとフレームの基礎（第6章）、★CSWSH（第7章）、メッセージ経由インジェクションなど他の脆弱性（第8章）。
- **Part C：統合・実践（第9〜10章）** — 実 CVE・実報告・報奨事例（第9章）、発展・方法論・防御の理解（第10章）。

★を付した第3・4・7章が、実害と「人間の実力差」が最も出る核である。とりわけ第4章の **alias/batching によるレート制限・2FA/OTP 総当りバイパス**と**循環参照を使った深いネスト DoS**、第7章の **Cookie 認証 WebSocket に対する CSWSH** は、自動ツールが苦手で報奨に直結しやすい。

## 学習の進め方（推奨5ステージ）

1. **基礎固め**：第1〜2章を読み、GraphQL エンドポイントで introspection 可否を判定し、無効時のスキーマ復元の考え方を理解する。
2. **認可の核**：第3章を精読し、スキーマから隠しフィールド/mutation を列挙して BOLA/BFLA を体系的にテストできるようにする。
3. **★武器化**：第4章に最も時間を割く。「HTTP リクエスト単位のレート制限を batching で実効 N 倍化する」原理を数値付きで説明でき、循環参照が DoS ベクタになる理屈を立証できるようにする（実行は必ずローカル演習環境で）。
4. **WebSocket/CSWSH**：第6〜8章。ハンドシェイクの Origin 検証欠如＋Cookie 依存という2条件を見抜き、CSWSH の PoC 構造を理解する。
5. **統合・実戦**：第9〜10章。実 CVE・実報告の「形」を数多く読み、防御チェックリストとして整理する。

## 安全のための約束（必読）

- **法・スコープ厳守**：DoS・総当り・バッチング攻撃は**本番で実行しない**。DVGA 等のローカル演習か、スコープ内で明示的に許可された対象に限定する。
- **数値は一次情報で裏取り**：商用ブログの CVE/CVSS 記述は誤りや版差を含みうる。NVD 等で確認する。
- **本書はラボ攻略（解答手順）を掲載しない**：演習は各自の手で、公式ラボまたは自前環境で行うこと。
