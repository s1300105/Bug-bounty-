# 序章 はじめに

## この本が扱うもの

HTTPリクエストスマグリング（HTTP Request Smuggling、別名 HTTPデシンク攻撃）は、**フロントエンド（リバースプロキシ・ロードバランサ・CDN）とバックエンドがHTTPリクエストの「境界」をどこと解釈するかがズレる**ことを突く脆弱性クラスです。1つのTCP接続に流し込まれたバイト列を、片方のサーバは「1つのリクエスト」と見なし、もう片方は「2つのリクエスト」と見なす——このわずかな解釈違いが、他ユーザーのリクエストの乗っ取り、認証バイパス、キャッシュ汚染へと連鎖します。

この分野は、**James Kettle（PortSwigger Research）**が2019年の "HTTP Desync Attacks: Request Smuggling Reborn" で現代的に再定義して以降、毎年のように新しい攻撃クラスが生まれてきた、Web脆弱性の中でも特に研究駆動で動いている領域です。本書はその研究系譜を軸に、以下を「武器になる」レベルまで積み上げることを狙います。

- **なぜ境界の解釈違いが起きるのか**（HTTP/1.1の`Content-Length`と`Transfer-Encoding`の二重性、HTTP/2ダウングレード）
- **古典的3分類**（CL.TE / TE.CL / TE.TE）の検出と悪用の型
- **Kettleの研究4部作＋State Machine**が切り開いた発展技法（CL.0・クライアントサイドデシンク・single-packet attack）
- スマグリングとしばしば連鎖する**Webキャッシュポイズニング／デセプション**
- 現実のバグバウンティ**実例・CVE**と、そこから逆算する検出・防御

## 想定読者と前提

- Webアプリケーションの基本（HTTP、リクエスト／レスポンス、プロキシの役割）を知っていること
- Burp Suite の基本操作（Repeater / Intruder）に触れたことがあること
- 手を動かす際は**PortSwigger Web Security Academy のアカウント**（無料）があると理想的

これらが未習でも読み進められるよう、第2章でHTTPの前提知識を、第3章で古典的分類の仕組みを丁寧に扱います。

## 本書の姿勢：防御と安全な検証

スマグリング系の攻撃は、他のWeb脆弱性と決定的に違う点があります。**攻撃の副作用が、無関係な他ユーザーのリクエストに及びうる**ことです。乱暴な検証は本番環境で他人のセッションを壊し、意図せぬ被害を生みます。そのため本書は一貫して次の姿勢を取ります。

- **原理と検出、防御を中心に**説明し、破壊的な完成形ペイロードや実在サービスへの無許可検証手順は書きません。
- 手を動かす学習は、**公式に用意された演習ラボ**（PortSwigger Web Security Academy 等）か、自分で構築した検証環境に限ります。
- 「安全な検証手法（他ユーザーへの副作用を避ける確認の仕方）」を、Kettleらの原典が強調する通り、実戦の前提として扱います。

これは倫理の話であると同時に、**優れたハンターの技術の一部**でもあります。副作用を制御できることは、報告の再現性と信頼性に直結します。

## 学び方（推奨ルート）

1. **第2〜3章で土台を固める**：HTTP前提知識と古典的3分類。ここが曖昧だと以降がすべて曖昧になります。
2. **第4章でKettleの系譜を通読**：各年の研究が「何を新しく可能にしたか」を軸に読むと、発展技法が地図の上に位置づきます。
3. **第5〜6章で発展技法とツール**：概念を理解した上で、HTTP Request Smuggler / Turbo Intruder がどう検出を自動化するかを見ます。
4. **第7〜8章でキャッシュ攻撃**：スマグリングと連鎖する強力な増幅器です。
5. **第9章で実例に当たる**：抽象概念が現実の報奨・CVEとしてどう結実したかを見て、第10章の防御・方法論で締めます。

各章は独立して参照もできますが、初読は順番通りを強く推奨します。
