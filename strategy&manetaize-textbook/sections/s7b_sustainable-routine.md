## 持続可能な働き方と学術研究に見るハンターの課題

前節では燃え尽き（burnout：長く続くストレスで意欲・集中力・成果が落ち、回復しにくくなる状態）が起きる仕組みを見ました。この節では「どうすれば何年も続けられるか」を扱います。材料は次の2種類です。

1. **現場の知恵**：フルタイムのハンターがポッドキャストやブログで語る、日々の過ごし方と休み方
2. **学術研究**：USENIX Security 2023 に採択された、ハンターの動機と課題を数値で並べた調査論文

前者は具体的ですが、個人の経験談にとどまります。後者は数百人のデータで裏づけがありますが、抽象度が高くなります。両方を突き合わせることで、「気合で乗り切る」話ではない、**仕組みとして続けられる働き方**を考えるのがこの節の目的です。

ロードマップはこの資料の位置づけを「**罪悪感なき休息、週1の無圧力デー**」としています。これはフルタイムハンターの間でよく語られる2つの原則を指しています。

#### 1-1. 罪悪感なき休息（guilt-free rest）

バグバウンティには**「今この瞬間も誰かが同じバグを探している」**という構造があります。報酬は先着1名にしか払われません（重複＝duplicate は通常無報酬）。そのため休んでいる時間が「機会損失」に感じられ、休憩中も頭の片隅でターゲットのことを考え続けてしまいます。これでは脳が回復しません。

対策は、休息を「サボり」ではなく**業務の一部として予定に組み込む**ことです。

```text
# 1日の設計例（考え方を示すための例）
08:00-12:00  深い作業ブロック  … 新機能の理解、手動テスト、PoC作成
12:00-13:00  休憩（画面から離れる）
13:00-16:00  中程度の作業      … 偵察結果の精査、仮説の検証
16:00-17:00  浅い作業          … レポート清書、トリアージへの返信
17:00-       終業。以降は通知を切る（ハードカットオフ）
```

**なぜこれが効くのか**
- **終業時刻を決めておくと、「今日はここまで」と判断する回数が1回で済む。** 終わりが決まっていないと「もう1時間だけ」を毎晩くり返し、判断のたびに意志の力を消耗します。
- **深い作業と浅い作業を分けると、コンテキストスイッチ（作業の切り替えで頭の中の状態を読み込み直すコスト）が減る。** 認証フローの状態遷移を頭に入れたままレポートの体裁を整えると、どちらの質も落ちます。

#### 1-2. 週1の無圧力デー（no-pressure day）

週に1日、**成果目標を一切置かない日**を作るという考え方です。この日はバグを探してもよいし、探さなくてもよい。新しい技術の論文を読む、ツールを整理する、何もしない。どれを選んでも「失敗」になりません。

**なぜ必要なのか**：フルタイムでは収入が成果に直結します。そのため毎日が「成果を出さねばならない日」になりがちです。バグが見つからない日が続くと、自己評価が収入と連動して下がり続けます（後述の USENIX 論文でも、何週間もバグが見つからない状態が「気が滅入る」と語られています）。**評価されない日を制度として用意する**と、この連動をいったん切ることができます。さらに、圧力がない状態での探索は、普段は優先度が低くて手を付けない領域への好奇心を育てます。これは長い目で見ると、新しい攻撃面の発見につながります。

### 2. スクリーンの外でバランスを取る

> ⚠️ **未取得の資料**: 「Breaking the Bug Bounty Burnout: Finding Balance Outside the Screen」（A Hacker's Blog）は自動取得できませんでした（理由: 取得時に HTTP 404 Not Found が返り、記事が移動・削除された可能性があるため）。以下のURLからご自身で直接ご覧ください: https://www.ahackersblog.com/p/breaking-the-bug-bounty-burnout-finding-balance-outside-the-screen

（以下は未取得資料の補足として一般知識に基づく解説です。検索で確認できた同じテーマの論点も含みます）

タイトルが示すとおり、この記事の主題は「**燃え尽きの解決策は画面の中にはない**」ということです。同じテーマの記事で共通して挙げられる対策を、原理と合わせて整理します。

#### 2-1. 燃え尽きのループを理解する

バグバウンティがつらい理由は、よく次の3つにまとめられます。

- **反復的**：偵察・列挙・テストという似た作業をくり返す
- **不確実**：どれだけ努力しても成果（有効なバグ）が出る保証がない
- **孤独**：多くの場合、一人で部屋にこもって作業する

**反復作業に結果が伴わないと、退屈が少しずつ燃え尽きに変わります。** これは心理学でいう「強化スケジュール」で説明できます。報酬がいつ出るかわからない変動比率スケジュールは、行動を強く持続させます（ギャンブルと同じ仕組み）。その一方で、報酬がない期間が長くなると、努力と結果の結びつきが失われ、無力感が生まれます。つまりバグバウンティは「やめにくいのに、報われにくい」構造を持っているのです。

#### 2-2. 画面の外での回復

| 対策 | 具体例 | なぜ効くか |
|---|---|---|
| 身体のケア | 定期的な休憩、健康的な食事、十分な睡眠、運動 | 長時間の画面作業は身体を動かさない。運動はストレスホルモンを下げ、睡眠は記憶の整理（学んだ手法の定着）に直接関わる |
| まったく関係のない活動 | ジム、ゲーム、散歩、趣味 | 同じ問題を考え続けると思考が固定される。脳が別の文脈に切り替わると、戻ったときに新しい視点で見られる（いわゆる「孵化効果」） |
| 時間の区切り | 20〜21時などにハードカットオフを置き、以降は罪悪感なく遊ぶ | 境界がないと仕事がすべての時間に染み出す |
| 仲間を持つ | 一緒に取り組むハンター仲間を作る | 孤独を和らげ、アイデアを交換できる。行き詰まりを言葉にすると、それだけで突破口が見えることも多い |

#### 2-3. 「燃え尽きた＝やめるべき」ではない

同じテーマの記事で強調されているのは、**燃え尽きは「やめろ」というサインではなく「関わり方を変えろ」というサイン**だという点です。具体的には次のような変え方があります。

- ターゲットや脆弱性クラスを変えて新鮮さを取り戻す
- 自動化できる反復作業はツールに任せる（第4章参照）
- 収入目標を短期（週・月）から長期（四半期・年）の平均で見るように変える

> 出典: Breaking the Bug Bounty Burnout: Finding Balance Outside the Screen（未取得）— https://www.ahackersblog.com/p/breaking-the-bug-bounty-burnout-finding-balance-outside-the-screen

### 3. 学術研究に見るハンターの課題と利点 ― USENIX Security 2023

ここからは本文を取得できた一次資料です。現場の経験談を、データで検証する材料になります。

#### 3-1. 論文の概要

- **題名**: *Bug Hunters' Perspectives on the Challenges and Benefits of the Bug Bounty Ecosystem*
- **著者**: Omer Akgul, Taha Eghtesad, Amit Elazari, Omprakash Gnawali, Jens Grossklags, Michelle L. Mazurek, Daniel Votipka, Aron Laszka（メリーランド大学、ペンシルベニア州立大学、UC バークレー、ミュンヘン工科大学、ヒューストン大学、タフツ大学）
- **学会**: USENIX Security Symposium 2023
- **データ収集時期**: 2019年5月〜2020年（コロナ禍初期を含む。プラットフォームの仕様などは当時のものなので注意）

これまでの研究は、プログラム側のデータ（レポート件数や支払額）から間接的にハンターの動機を推測するものがほとんどでした。この論文は、**ハンター本人に直接聞き、要因の重要度を数値で順位づけした**点が新しいところです。

#### 3-2. 研究方法 ― 3段階の調査

| 段階 | 人数 | 目的 |
|---|---|---|
| ① フリーリスティング（自由列挙）調査 | n=56 | 「プログラム選びで考えること」「課題」「利点」「便利なプラットフォーム機能」を思いつく限り挙げてもらい、要因を洗い出す |
| ② 要因評価調査 | n=159 | ①で得た **54要因** を7段階のリッカート尺度（「非常に重要」〜「全く重要でない」のような段階評価）で評価してもらう |
| ③ 半構造化インタビュー | n=24（平均43分） | 「なぜその要因が重要なのか」を掘り下げる |

**方法論のポイント（なぜそうするのか）**

リッカート尺度の回答を1〜7の数値にして平均するやり方は一般的ですが、統計学者からは批判されています。「非常に重要」と「とても重要」の差が、「とても重要」と「やや重要」の差と等しいとは限らないからです。そこでこの論文は、**対数線形 Bradley-Terry（LLBT）モデル**を使っています。これは「要因Aが要因Bより高く評価されたかどうか」という**比較だけ**を使って、各要因の相対的な重み π（worth）を推定する方法です。要因 j が要因 k より好まれる確率は次の式で表されます。

```text
p(f_j > f_k) = π_j / (π_j + π_k)
```

**読み方**：π はグループ内の相対値です。π=0.191 の要因は、π=0.095 の要因とくらべて、一対比較で約2倍「勝ちやすい」ことを意味します（0.191/(0.191+0.095) ≈ 0.67）。**π の値を比べてよいのは同じ要因グループの中だけ**で、「課題」の π と「利点」の π を直接比べることはできません。

参加者の特徴（②の159人）：男性がほぼ全員、18〜29歳が124人、南アジア在住が64人で最多。週の作業時間は「5〜10時間」が53人で最多、「40時間超」は3人だけ。**年収で見ると、バグバウンティ収入が年7万5千ドル以上の人は12人（約8%）にとどまり、1,000〜29,999ドルが57人で最多**でした。つまり調査対象の大半は、フルタイムではなく**副業・パートタイムのハンター**です。

#### 3-3. 主な結果（1）利点 ― お金と学び

| 利点 | π | 備考 |
|---|---|---|
| 金銭的報酬 | 0.191 | 1位 |
| 学習・スキル向上 | 0.170 | 2位 |
| 楽しさ・挑戦 | 0.140 | |
| 法的セーフハーバー | 0.118 | ルールを守れば訴えられないという約束 |
| **柔軟性**（時間・場所） | 0.095 | 中位 |
| キャリア | 0.091 | |
| コミュニティ | 0.071 | |
| 利他性（ネットを安全にしたい） | 0.062 | |
| **評判（レピュテーション）** | 0.048 | 下から2番目 |
| 非金銭報酬（グッズ等） | 0.013 | 最下位 |

先行研究では「評判は金銭と同じくらい重要かもしれない」という仮説がありましたが、**評判は最も重要度の低い動機の一つ**という結果になりました。これはメンタル管理の点でも示唆があります。リーダーボードの順位に一喜一憂するのは、多くのハンターが本当に大事にしている価値（収入と学び）とずれている可能性が高いということです。

学習については、公開済みレポートを読むことが最もよく挙げられた学習方法でした（I=18。I はインタビューで言及した人数）。一方で、3人は**「学び続けなければならない圧力」自体がつらい**と語っています。

> 「どれだけ経験を積んでも、毎日新しいことを学ぶ必要がある。これがバグハンティングを少し難しくしている理由の一つだと思う。学ぶのをやめたら、感覚を失ってしまう。」（インタビュー参加者の発言、筆者訳）

#### 3-4. 主な結果（2）課題 ― 最大の問題はコミュニケーション

| 課題 | π |
|---|---|
| 反応の遅さ・無反応 | 0.130（1位） |
| 対応への不満（重大度の引き下げ等） | 0.120 |
| スコープ（対象範囲）の不明確さ | 0.082 |
| プラットフォームの支援不足（仲裁など） | 0.079 |
| 重複（duplicate） | 0.078 |
| 専門外の資産 | 0.068 |
| 堅牢すぎる資産 | 0.064 |
| **ストレスと不確実性**（燃え尽きの恐れ、孤立、不規則な収入） | 0.062 |
| 雑務（CAPTCHA、タイムアウト、テスト用アカウント作成） | 0.050 |
| 退屈 | 0.050 |
| … | … |
| 法的脅威 | 0.028 |
| 言語・コミュニケーション能力 | 0.014 |

注目したいのは、**上位の課題の多くが「ハンター自身ではどうにもならない」もの**だという点です。反応の遅さ、評価の引き下げ、スコープの曖昧さは、すべてプログラム側に原因があります。これはメンタル管理の考え方にもつながります。**自分でコントロールできないことに感情を預けると消耗する**ということです。前章（第6章）で扱った重複・紛争への向き合い方は、ここに直結します。

インタビューでは、重複への対処法として次のようなものが語られました（I=9）。
- 見つけたバグが「認識された」とわかるだけで救われる（3人）
- 元のレポートに追加してもらえると（報酬がなくても）、プログラムが嘘をついていない証拠になる（4人）
- コミュニティで人気のバグは狙わない（2人）

#### 3-5. 主な結果（3）ギグワークの光と影 ― 本節の核心

ロードマップがこの論文を取り上げた理由がこの節です。**ギグワーク**（雇用契約ではなく、成果ごとに単発で報酬を受け取る働き方）であることが、ハンターに利点と重い負担の両方をもたらしています。

**利点：柔軟性（π=0.095）**
多くのインタビュー参加者（I=14）が柔軟な勤務時間を挙げました。

> 「プロジェクトごとに締め切りのあった開発者の仕事と比べて……ここには締め切りがない。」

ただし、柔軟性にも落とし穴があることが語られています。
- **自分で勤務時間を管理するのは難しい**
- **本業としてフルタイムで取り組むと、「いつでも働ける」ことの意味が薄れる**：「好きな時にできる……でもバグバウンティが唯一の仕事だったら、もっと難しいかもしれない」
- **参入障壁が低いというのは見かけだけ**：効果的に参加できるまでに何年もかけてスキルを積んだという声（2人）

**負担：支払いの不確実性**
報酬が出るのは「一意で有効」と判断されたバグだけです。そのため、**大きな労力をかけても無給に終わることがあります**。最もよく挙げられた不確実性の原因は支払いでした（I=9）。いつバグが見つかるか、認められるか、いつ支払われるか、どれもわかりません。4人は、**バグバウンティが主な収入源の場合、収入の不規則さが特にストレスになる**と語りました。

> 「何日も、ときには何週間も、バグが一つも見つからないことがある。これはかなり気が滅入る。この仕事全体の暗い側面だと思う。」

この不確実性は**競争**によってさらに強まります（「バグバウンティは基本的に競争で、早い者勝ちだ」）。期間限定のイベントは競争意識をいっそう強めます（3人）。先に見つけたとしても、次はプログラム担当者に有効性を納得してもらう必要があります。

**対処法：本業を持つ、休む、貯蓄する**

論文が示した対処法は次の3つです。

1. **本業（フルタイムの仕事）を持ち続ける**（4人）。

   > 「私にはフルタイムの仕事があって、それで収入がずっと安定している。もしバグバウンティをフルタイムでやっていたら……メンタルヘルスに影響していたかもしれない。」

2. **休みを取る**（3人）。

   > 「燃え尽きたと感じたら、別のことをする。トレーニングの講師をするとか……散歩に行くとか。」

3. **不確実性があるからフルタイムにしない**（5人）。高収入の可能性があっても、不安定さに見合わないという判断です。

   > 「本気でやれば、バグバウンティで15万ドル以上稼げる可能性はある……でもお金が入ってくる時期がばらばらなのが問題だ。本気でフルタイムでやるつもりなら、ある程度の貯蓄が必要だ……いざというときに持ちこたえられるように。」

一方で、フルタイムのハンターである参加者も1人おり、「バグバウンティはそれ自体で正当なキャリアになりうる」と主張する人もいました。**フルタイムを否定しているわけではない**点に注意してください。

#### 3-6. この論文から導く「持続可能な働き方」の原則

論文のデータと第1〜2項の現場知見を組み合わせると、次の原則が導けます。

**原則1：収入の分散（ポートフォリオ化）**
収入の不確実性を個人の努力で消すことはできません。**仕組みで吸収する**必要があります。具体的には、本業・契約ペネトレーションテスト・講師業・コンテンツ制作など、**バグバウンティ以外の安定収入を持つ**ことです。論文の参加者が言う「トレーニングの講師をする」は、休息と収入源の分散を兼ねた好例です。

**原則2：フルタイム化の前に生活費の緩衝材を用意する**
論文中の「ある程度の貯蓄が必要」という発言は、キャッシュフローの問題として理解できます。バグバウンティの収入には、次の3つの遅れと不確実性が重なります。

```text
バグ発見 ──(トリアージ待ち: 数日〜数週間)──> 有効判定
         ──(重大度確定・支払い待ち: 数週間〜数か月)──> 入金
+ 重複・N/A・重大度引き下げによる「ゼロ」または「減額」の可能性
```

生活費は毎月決まって出ていきますが、収入は不規則に、しかも遅れて入ってきます。このずれを埋めるのが貯蓄（ランウェイ＝収入がゼロでも生活できる期間）です。何か月分が必要かは個人の生活水準と過去の収入のばらつきで決まり、論文は具体的な数値を示していません。ただし、「**直近の最も収入が少なかった期間の長さ**」を下回らない水準にしておくのが合理的な考え方です。

**原則3：コントロールできない課題と感情を切り離す**
課題の上位（反応の遅さ、評価への不満、スコープの曖昧さ）はプログラム側の問題です。対処の選択肢は次のとおりです。
- 反応の良いプログラムを選ぶ（公開レポートでトリアージの質を見極める。論文では10人がこの使い方をしていました）
- スコープが明確なプログラムを優先する
- 1件のレポートの結果に一喜一憂せず、**月・四半期単位の期待値**で評価する

**原則4：評判より学びを軸にする**
評判が最も重要度の低い動機の一つだったという結果は、リーダーボードを追いかけることで生まれる消耗を見直すきっかけになります。成果が出ない期間も「学び」は積み上がります。**学習ログを付けておくと、無収入の週でも前進を実感できます**（第3章の学習ノート参照）。

**原則5：孤立を避ける**
インタビューでは、コミュニティとの交流が**リモートで一人で働く孤立を和らげる**効果が語られました（I=2）。特に対面イベントは帰属意識をもたらします。協力関係から共同でバグを見つけるようになった例（5人）もあります。

#### 3-7. 論文による業界への提言（防御側・運営側の視点）

この論文は、ハンター個人ではなくエコシステムの改善策も提言しています。プログラムを運営する防御側にとっても重要な内容です。

| 対象 | 提言 |
|---|---|
| **プログラム** | スコープを明確にし、常に最新に保つ（低コストで効果大）。人員を増やして反応を速くする。増員が無理なら、**状況をこまめに透明に伝える**だけでも不確実性は減る。バウンティ表に過去の支払い例を載せる。担当者にハンターとのコミュニケーションを訓練する |
| **プラットフォーム** | 仲裁が偏っているという不信に対して、ビジネスモデルを明確に説明し、仲裁結果の定期報告で透明性を高める。プログラムが仲裁結果を受け入れない場合でもハンターに支払われる**保険制度**を検討する。学習資料を公開済みレポートと結びつける |
| **政策立案者** | 善意のセキュリティ研究者全般を対象にした法的セーフハーバーを整備する。労働規制当局がギグワークに伴う不確実性・搾取から**コミュニケーションと支払いの基準**でハンターを守る。予算の少ない重要分野（医療・金融など）のプログラムを助成する |

これらの提言は、**ハンターのメンタル負荷の多くは個人の弱さではなくエコシステムの構造から生じている**、という論文の結論を反映しています。

**時事性の注意**：データは2019〜2020年のものです。その後、主要プラットフォームは応答時間の SLA（サービス水準の約束）表示や、セーフハーバー条項の標準化（例：Gold Standard Safe Harbor 等）を進めています。ただし論文の中核となる構造、つまり**成果報酬ゆえの支払いの不確実性、先着競争、プログラム側に最終判断権があること**は、2026年時点でも本質的に変わっていません。

> 出典: Bug Hunters' Perspectives on the Challenges and Benefits of the Bug Bounty Ecosystem（Akgul et al., USENIX Security 2023）— https://www.usenix.org/system/files/sec23fall-prepub-81-akgul.pdf

### 4. まとめ ― 続けるための設計チェックリスト

| 観点 | 問い | 根拠 |
|---|---|---|
| 収入 | バグバウンティ以外に安定収入があるか。ないなら、十分なランウェイ（貯蓄）があるか | USENIX論文：本業が収入安定とメンタル保護に寄与 |
| 時間 | 終業時刻（ハードカットオフ）を決めているか。深い作業と浅い作業を時間帯で分けているか | CTBBノート（検索要約）、燃え尽き対策記事 |
| 休息 | 罪悪感なく休める時間と、週1の無圧力デーを予定に入れているか | ロードマップ上の位置づけ（CTBBノート） |
| 身体 | 睡眠・食事・運動を「生産性の基盤」として扱っているか | CTBBノート（検索要約） |
| 評価軸 | 評判や短期の成果ではなく、学びと長期の期待値で自分を評価しているか | USENIX論文：評判は下位、学習は2位 |
| 外部要因 | 反応の遅さ・評価の引き下げを「自分の失敗」と混同していないか。反応の良いプログラムを選んでいるか | USENIX論文：課題上位はコミュニケーション |
| つながり | 仲間・コミュニティとの接点があるか | USENIX論文・燃え尽き対策記事 |

「燃え尽きないハンター」は、特別に強い精神を持っているわけではありません。**不確実性を収入構造で吸収し、休息を予定に組み込み、自分ではコントロールできない課題と自己評価を切り離す**という仕組みを持っているのです。
