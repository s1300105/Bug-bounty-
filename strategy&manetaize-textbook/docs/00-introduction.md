# 序章 本書の位置づけと読み方

## この本は誰のためのものか

本書の読者は、すでに脆弱性の「武器」を持っている人だ。Recon の回し方を知り、XSS・SSRF・IDOR・認証まわり・GraphQL といった脆弱性クラスを一通り扱える。にもかかわらず、思うように成果（報奨・受理）が出ない——あるいは、出ているが持続できるか不安がある。そういう段階の人に向けて書いた。

なぜなら、この段階でボトルネックになるのは**個別技術ではなく「How」だから**だ。同じ武器を持っていても、①どのプログラムに時間を投下するか、②寝ている間に攻撃対象領域の変化を捉える自動化を持っているか、③同じバグを $100 のレポートにするか $1,000 のレポートにするか、④長い dry spell と duplicate の連続に心を折られず続けられるか、⑤収益をどう安定させキャリアにつなげるか——ここで勝敗が分かれる。技術は「武器」、本書が扱うのはその武器を実戦で回す「OS（運用体系）」である。

## 5つの領域と9段階

トップハンターの二次資料を横断すると、運用の核は次の5領域に収束する。

1. **プログラム選定と時間配分** — 有限な時間をどこに投下するか（第2章）
2. **自動化基盤** — 継続監視・差分検知・通知で「発見」を生む仕組み（第4章）
3. **レポート品質と報奨交渉** — タイトル・再現手順・impact の物語化（第6章）
4. **メンタル管理・燃え尽き対策** — フィードバックループの断絶に負けない継続（第7章）
5. **収益化・コラボ・キャリア** — べき乗分布の現実を踏まえた設計（第8章）

本書はこれを Lv1〜Lv9 の段階として展開する。各段階には「なぜ必要か」と「実在が確認できる二次資料」を対応させた。

## 現実認識という武器

本書の前提として、まず「現実」を直視してほしい。これは意欲を削ぐためではなく、**正しい期待値を持つことが最大のメンタル防御であり戦略になる**からだ。

- **受理率は構造的に厳しい**。Meta の2024年実績では約1万件の報告のうち有効は約600件（受理率およそ6%）だった。duplicate や NA（Not Applicable）は初心者で50〜80%、経験者でも20〜40%が普通だと報告されている。
- **収益はべき乗分布（power law）**。トップ1%が下位90%の合計を上回るとされ、SNSで流れる高額報奨は例外的な上澄みである。有効バグあたりの報奨中央値は数百ドル規模という調査もある。
- **燃え尽きは初心者ではなく経験者を襲う**。パターンを知り尽くして作業が機械的になり、努力と報酬が乖離してフィードバックループが切れるためだ。

この現実を踏まえるからこそ、「継続」「重複回避」「impact の物語化」「コラボ」「休息の習慣化」が効いてくる。数字に打ちのめされるのではなく、数字を戦略の設計図として使うこと——これが本書全体を貫く姿勢である。

## 本書の限界と使い方の注意

本書は**原典（一次・二次資料）を直接取得して**書いているが、いくつか限界がある。

- 内容の多くは**二次資料**（ハンターのブログ・ポッドキャスト・プラットフォームの解説記事）に基づく。数値（収入・受理率・報奨額）は自己申告や特定時点の実績を含むため、**必ず最新の一次情報で裏取り**してほしい。
- 生成時にネットワーク上の理由で取得できなかった資料は、本文中に `⚠️ 未取得` と注記し、[付録B](99-appendix.md#付録b-取得できなかった資料)に URL と理由を一覧化した。
- 有料教材への言及は事実の紹介であって購入推奨ではない。

読み方は自由だが、迷ったら「序章 → ★の第1・4・6・7章 → 残り → 付録」の順を勧める。それでは第1章から始めよう。
