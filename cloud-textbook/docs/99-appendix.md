## 付録C: 用語集

- **SSRF (Server-Side Request Forgery)**: サーバー側アプリケーションに任意のURLへリクエストを発行させる脆弱性。クラウドではメタデータサービスへの到達手段になり最高インパクトに直結する。
- **IMDS (Instance Metadata Service)**: EC2インスタンス等が自身の情報とIAMロールの一時クレデンシャルを取得する内部HTTP API。`169.254.169.254` でリッスンする。
- **IMDSv1 / IMDSv2**: IMDSv1はGET一発でクレデンシャルを返す旧方式。IMDSv2はPUTでトークン取得→ヘッダ付与の2段階＋hop-limitで多くのSSRFを防ぐ。ただしIMDSv1併存などの条件で破れる。
- **IAM (Identity and Access Management)**: AWSの認証・認可基盤。ユーザー・ロール・ポリシー・信頼関係でアクセスを制御する。
- **一時クレデンシャル**: STSが発行するAccessKeyId/SecretAccessKey/SessionTokenの組。有効期限があり、ロール引き受け時に払い出される。
- **AssumeRole / STS**: Security Token Service。ロールを引き受けて一時クレデンシャルを得る仕組み。信頼ポリシーが引き受け可能な主体を定義する。
- **PassRole**: IAMロールをAWSサービス（EC2/Lambda等）に手渡す権限。強力なロールを渡せると権限昇格の踏み台になる。
- **権限昇格 (Privilege Escalation)**: 低権限のプリンシパルがポリシー操作系やPassRole系のActionを悪用して、より高い（多くは管理者相当の）権限を獲得すること。
- **メタデータサービスのヘッダ要求**: GCPは `Metadata-Flavor: Google`、Azureは `Metadata: true` を必須とする最小限の防御。単純なSSRFの一部を防ぐ。
- **S3バケット誤設定**: 公開ACL・バケットポリシー・ACLの書き込み許可などにより、非公開想定のオブジェクトが読み書きされてしまう設定ミス。
