# 序章：この本の狙いと読み方

## なぜ「クラウド／IAM攻撃」を学ぶのか

オンプレミス時代のSSRFは、多くの場合「内部ネットワークのスキャン」や「内部サービスへの限定的なアクセス」で止まった。ところがクラウドでは事情が一変する。EC2インスタンスの内側には `169.254.169.254` というメタデータサービス（IMDS）が存在し、**認証なしで、そのインスタンスに紐づくIAMロールの一時クレデンシャルを配ってしまう**。つまりSSRF一発が、クラウドアカウントの権限そのものを攻撃者の手に渡す入口になり得る。

この威力を世界に知らしめたのが2019年のCapital One事件だった。SSRF → IMDS → 一時クレデンシャル窃取 → S3バケット大量アクセス、という連鎖で約1億600万人分の情報が流出し、巨額の制裁金と和解金に至った。以降、**SSRF→メタデータ→クレデンシャル窃取→IAM権限昇格→アカウント乗っ取り**は、バグバウンティでも実際のインシデントでも「最高インパクトの王道」として繰り返し観測されている。

本書は、この連鎖を軸に10章で体系立てて学ぶ。目的はあくまで**防御**——攻撃の原理と経路を正確に理解し、自組織の設計・検知・修正に活かすことにある。

## 本書の構成

- **第1章**で責任共有モデルとIAM/STSの基礎を攻撃者視点で押さえる。ここが読めないと後段の「何が窃取でき、何に悪用できるか」が読めない。
- **第2章**が本書の核。IMDSv1/v2の違い、SSRFからの到達手法、フィルタ回避の原理、GCP/Azureのメタデータ、そしてCapital One事件を扱う。
- **第3〜7章**で、窃取後の権限列挙、S3攻撃、IAM権限昇格、サーバレス/コンテナ/Secrets、シークレットReconと、連鎖の各段を深掘りする。
- **第8章**でPACU/CloudFox/ScoutSuite/Prowlerといったツールを整理し、**第9章**で実際の開示報告・ライトアップを読み解く。
- **第10章**でテスト方法論・防御理解と、手を動かすための常設ラボ（flaws.cloud、CloudGoat、IAM Vulnerable 等）を案内する。

## 読み方と前提

- **前提知識**：HTTPとSSRFの基本、コマンドライン操作、AWSの用語（EC2/S3/IAM）に軽く触れたことがあると読みやすい。未習でも各章が最小限の前提を補う。
- **手を動かす場所**：本書の実験は、必ず自分の管理下にあるアカウントか、学習用に設計されたラボ環境の中だけで行うこと。他者のサービス・本番環境への無許可の検証は行わない。
- **鮮度に注意**：クラウドのデフォルト挙動（例：新規EC2でのIMDSv2の扱い、各サービスの既定設定）は頻繁に更新される。本書の記述と実環境が食い違う場合は、**常に公式ドキュメントと一次ソースを優先**すること。
- **一次資料の取得について**：本書はロードマップ記載URLを機械的に取得して執筆したが、一部はボット対策やSPA化で本文を取得できなかった。該当箇所には注記があり、対象は[付録B](99-appendix.md#付録b-取得できなかった資料)に一覧化している。重要な判断の前には原典を直接確認してほしい。

## 倫理と法

クラウド攻撃の知識は、防御と攻撃のどちらにも使える両刃の剣である。本書の内容は、**明示的な許可のある範囲**（自分の環境、公式の学習ラボ、スコープが定義されたバグバウンティ/ペンテスト）でのみ用いること。無許可のアクセスや破壊的操作は、多くの国で犯罪であり、本書の目的にも反する。
