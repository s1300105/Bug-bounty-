# クライアントサイド脆弱性ハンティングの基盤技術を極める教科書

クライアントサイド脆弱性を「見つけられる」ようになるための**基盤技術**を、原典に忠実に学ぶ日本語教科書です。バグバウンティ／脆弱性リサーチ／フロントエンド防御実務を志す中〜上級者を主な読者に想定しています。

本書の前提となる考え方はひとつです。**クライアントサイド脆弱性を見つける力の核は、個別の穴（XSS/CSRF等）のペイロード知識ではなく、ブラウザの動作原理とセキュリティモデルの理解・JavaScriptの深読解・変形済みコード（minify/難読化/bundle）の解析・source→sinkのデータフロー追跡という4つの土台にある。** 全9章はこの4本柱をLv1〜Lv8の段階に沿って積み上げる構成になっています。

本書は「クライアントサイド脆弱性ハンティングの基盤技術習得ロードマップ」（本リポジトリ `roadmaps/clientside.md`）を土台に、掲載された各資料を実際に取得して要約・再構成したものです。リンク集ではなく、**読んで理解が完結する**ことを目指した教材です。

## 使い方

- **通読する**: 第1章から順に読むと、ブラウザ内部 → セキュリティモデル → JS読解 → リバースエンジニアリング → DevTools → Burp/DOM Invader → 攻撃面マッピング → 発展領域、と土台から応用へ積み上がります。
- **辞書的に引く**: 左サイドバー（章一覧）と各ページ右の目次、上部の全文検索で、必要な技法だけをピンポイントで参照できます。
- **手を動かす**: 本書は「読む→ラボで手を動かす→実際のJSバンドルで再現」のループを前提にしています。PortSwigger Web Security Academyのラボと Burp DOM Invader を軸に据えるのが最短経路です。
- **原典に当たる**: 各節末に「出典」を明記しています。ブラウザ挙動やツールの仕様はバージョン依存が激しいため、実際に使う前に必ず原典で最新状態を確認してください。

## 重点章（投資対効果が最も高い場所）

ロードマップの判断に従い、本書でも次の3つを重点に置いています。

- **第4章 クライアントサイドコードのリバースエンジニアリング** — 自動ツールやAIが最も苦手とし、手作業の実力が最も効く領域。
- **第5章 ブラウザDevToolsの徹底活用** — source→sinkの手動追跡そのもの。
- **第6章 プロキシと専用ツールによる動的解析（DOM Invader）** — canaryによるデータフロー自動追跡で、数千行のminifiedコードでもsinkと文脈を把握できる。

## 段階的な進め方（目安）

- **ステージ1（2〜3週間）: 土台の地図を作る** — 第1〜2章を通読。ゴール：DevToolsのNetwork/Applicationで、あるサイトのCORSヘッダ・Cookie属性・CSPを読んで「この設定は緩い/厳しい」を言語化できること。
- **ステージ2（3〜4週間）: JS読解とDevToolsを鍛える** — 第3章で言語仕様を固めつつ、第5章のデバッグを毎日実践。ゴール：conditional breakpointとevent listener breakpointを使い、あるDOM更新の原因コードを5分以内に特定できること。
- **ステージ3（4週間〜、最重要）: リバースエンジニアリング＋DOM Invader** — 第4章と第6章を並行。ゴール：JSバンドルから隠れAPIエンドポイントと危険なsinkを列挙し、source→sinkのデータフローを1本再現できること。
- **ステージ4（継続）: 攻撃面マッピングと発展領域** — 第7章の方法論で自分のチェックリスト（source一覧×sink一覧×置くべきbreakpoint）を作り、第8章のService Worker/WebSocket/拡張/WASMへ拡張する。

**次に進む／戻るの判断基準**

- 第4章のbundle解析で「読めない/追えない」箇所が半分以上なら、第3章のJS基礎に戻る。
- DOM Invaderが検出したsinkの意味を説明できないなら、第2章（sink＝なぜ危険か）と第5章（手動追跡）を補強する。
- recon自動ツールの出力を鵜呑みにして誤検知を選別できないなら、第4章の手動解析比率を上げる。

## 本書の限界（重要）

- **教育・防御・許可された検証のための教材です。** 解析や検証は、自分が所有するシステム、明示的に許可されたシステム（バグバウンティのスコープ内、意図的に脆弱なラボ）に対してのみ行ってください。実在サービス・本番環境への無許可の検証や、破壊的な手順は本書では扱いません。source map復元やJS reconも「公開されているクライアントサイド資産の解析」に留め、対象プログラムの規約／スコープを厳守してください。
- **陳腐化に注意。** ブラウザの内部挙動、DevToolsのUI、Burp/DOM Invaderの機能、deobfuscation・source map・recon系ツール（webcrack, de4js, sourcemapper, LinkFinder, SecretFinder, jsluice等）のメンテ状況は、バージョンや時期に強く依存します。GitHubのstar数・最終コミット・Issueを都度確認してください。古いツールはPython環境依存で動かない場合があります。
- **自動取得できなかった資料があります。** ログイン必須・Bot対策・ペイウォール・JS依存レンダリング等で原典を完全反映できなかった資料は、[付録B](99-appendix.md)に理由つきで一覧化しています（77件中15件）。該当箇所は本文中にも警告を挿入し、一般知識に基づく補足であることを明示しています。
- **HackTricksのドメイン移行。** HackTricksは `book.hacktricks.xyz` → `hacktricks.wiki` への移行が進行中で、一部リンクはミラー／リダイレクト（およびペイウォール）になる場合があります。本書では可能な範囲で公式GitHub rawミラーから内容を取得しています。
- **コミュニティ発の2次資料を含みます。** Medium/gist/個人ブログ由来の資料は品質の高いものを選んでいますが、著者の主張や手順が最新のブラウザ挙動と食い違う可能性があるため、PortSwigger/Chrome公式で裏取りしてください。
