# 序章 — 本書の狙いと読み方

## この本は何か

本書は、**SQLインジェクション（SQLi）を「なぜそうなるのか」の原理まで含めて体系的に理解する**ための日本語教科書です。単なるペイロード集やチートシートの寄せ集めではなく、権威ある原典（PortSwigger Web Security Academy、OWASP、HackTricks、PayloadsAllTheThings、pentestmonkey、各種ベンダー研究、IPA・徳丸本）の内容を実際に取得し、要点を落とさずに日本語で再構成しています。読者が原文を読まなくても要旨を追え、かつ原文に戻る足がかりになることを目指しています。

## 想定読者

- Webアプリケーションの基本的な仕組み（HTTP、フォーム、リクエスト／レスポンス）と、SQLの初歩（SELECT、WHERE、テーブルとカラム）は既知の中〜上級者。
- バグバウンティ・脆弱性診断・セキュリティリサーチに取り組む人、あるいは開発者として堅牢な防御を実装したい人。

素朴な基礎（「SQLとは」「HTTPとは」）の説明は最小限にとどめ、**攻撃と防御の原理・DBMSごとの差異・現代的なトピック**に紙面を割いています。

## SQLiのメンタルモデル（全体像）

本書全体を貫く一本の軸は、次の一文に集約されます。

> **SQLiの根本原因は「信頼できないデータ」と「クエリの構文（コード）」が分離されずに混ぜられることにある。**

アプリが文字列連結でSQL文を組み立てると、ユーザー入力の中の `'` やキーワードが「データ」ではなく「構文」として解釈され、攻撃者がクエリの意味そのものを書き換えられてしまいます。これが、in-band（UNION・エラー）でも、blind（boolean・time・OOB）でも、second-orderでも、あらゆる変種に共通する核心です。そして防御の決定打である**パラメータ化クエリ（プリペアドステートメント）**は、この「データと構文の分離」をプロトコルレベルで強制することで効きます（第8章）。

各章はこのメンタルモデルの異なる側面を扱います。

1. **第1章 基礎** — SQLiのメンタルモデルとテスト方法論の枠組み。
2. **第2章 in-band** — UNION・エラーベースで直接データを抜く中核技法。
3. **第3章 Blind** — 出力が無い状況で1ビットずつ推測する（boolean/time/OOB）。
4. **第4章 DB別技法** — MySQL/PostgreSQL/MSSQL/Oracle/SQLiteのクセと差異。
5. **第5章 WAF回避** — シグネチャフィルタをエンコード・難読化・代替構文で潜り抜ける。
6. **第6章 応用・現代トピック** — second-order、ORM/NoSQL/GraphQL、SQLi→RCE。
7. **第7章 ツール** — sqlmap/Ghauriを専門家として操り、手動が勝る場面を見極める。
8. **第8章 防御** — なぜパラメータ化が効くのか、コードレビュー、検出。
9. **第9章 練習** — 反復量を積むためのプラットフォームと継続学習。
10. **第10章 リファレンス** — 定番書籍・常設チートシート。

## 読み方の指針

- **読む＋手を動かすをセットに。** 各章の理論を、対応するラボ（第9章）で必ず具体化してください。特に第3章のblind抽出は、二分探索スクリプトを自作するのが最良の練習です。
- **DBMSごとのノートを作り続ける。** コメント構文・文字列連結・メタデータ表・バージョン取得は、DBMSで大きく異なります。第4章の比較を自分の手元表に育ててください。
- **倫理と法を最優先に。** 本書の技法は、許可された対象（自分の環境、バグバウンティのスコープ、意図的に脆弱なラボ）に対してのみ用いてください。

それでは、第1章から始めましょう。
