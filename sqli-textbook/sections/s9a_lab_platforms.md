## 主要ラボプラットフォーム

これまでの章で、UNION攻撃・ブラインドSQLi・二次注入・WAFバイパス・SQLiからRCEへのエスカレーションといった技法を体系的に学んできた。しかし、SQLインジェクション（SQLi、SQL injection。アプリケーションが組み立てるSQLクエリに攻撃者が任意の構文を紛れ込ませ、データベースへの問い合わせ内容そのものを書き換える攻撃）は座学だけでは身につかない。実際にペイロードを打ち込み、レスポンスの微妙な差分を観察し、「なぜこのクエリがこう解釈されたのか」を自分の手で検証するプロセスを繰り返すことで初めて定着する技術である。

本節では、継続的な演習環境として代表的な3つのプラットフォーム――**PortSwigger Web Security Academy**、**sqli-labs**（セルフホスト型）、**TryHackMe SQL Injectionルーム**――を取り上げ、それぞれの特徴・対象レベル・使い方・学習上の位置づけを整理する。3つは互いに補完関係にあり、「まず何を、どの順で、どこまでやるべきか」という具体的な学習ロードマップも併せて示す。

### PortSwigger Web Security Academy — 最高品質の無償ラボ群

#### 概要

[PortSwigger Web Security Academy](https://portswigger.net/web-security/sql-injection) は、Burp Suiteの開発元であるPortSwigger社が無償公開している、Web脆弱性学習のための業界標準教材である。SQLiのページでは、まず脆弱性そのものを次のように定義している。

> SQL injection is a web security vulnerability that allows an attacker to interfere with the queries that an application makes to its database.

（SQLインジェクションとは、攻撃者がアプリケーションがデータベースに対して発行するクエリに干渉できてしまうウェブセキュリティ脆弱性である。）

> 出典: SQL injection — https://portswigger.net/web-security/sql-injection

この「干渉できる（interfere with）」という表現が核心であり、SQLiの本質は「本来アプリケーション開発者が固定するつもりだったSQL構文の一部を、ユーザー入力によって動的に書き換えられてしまう」ことにある。バックエンドがユーザー入力を文字列結合でSQL文に埋め込み、DBMSのパーサ（構文解析器）に渡す際、入力に含まれる引用符やSQLキーワードがエスケープされていないと、パーサは「データ」のつもりで受け取った文字列を「構文（コード）」として解釈してしまう。これがSQLi全般の根本原因である。

#### ページが解説する主要な攻撃パターン

Web Security Academyのトップページでは、SQLiの代表的な悪用パターンを次の4カテゴリに整理している。

1. **隠れたデータの取得（Retrieving hidden data）**: クエリの条件式を書き換え、本来表示されないはずのデータ（非公開商品、他ユーザーの注文など）を結果セットに含めさせる。
2. **アプリケーションロジックの破壊（Subverting application logic）**: 認証クエリの条件を常に真にすることでログイン処理などを回避する。
3. **UNION攻撃（UNION attacks）**: `UNION SELECT` を注入して、本来のクエリが参照していない別テーブルのデータを同じレスポンス内に抽出する。
4. **ブラインドSQLインジェクション（Blind SQL injection）**: クエリ結果が画面に直接表示されないシナリオで、真偽差分や応答遅延などの間接的なシグナルから情報を1ビットずつ推測する。

これらはいずれも本教科書の第2章・第3章で詳しく扱った内容と対応しており、Academyのラボは「読んだ理論を実際に手を動かして検証する場」として設計されている。

#### ラボの難易度体系と構成

Academyの各トピックには、レベル別にラベル付けされたラボが用意されている。

- **APPRENTICE（見習い）**: 基礎技法を単体で試す、最も易しいラボ。UNIONベースの単純な抽出やログインバイパスなど、1つの脆弱性クラスを最短経路で悪用できれば解ける。
- **PRACTITIONER（実践者）**: 複数の防御（一部の文字がフィルタされている、エラーメッセージが抑制されているなど）が組み合わさり、より現実に近い試行錯誤を要求される。
- **EXPERT（専門家）**: フィルタのバイパス、二次注入、複雑なブラインド抽出の自動化など、実務レベルの応用力が問われる最難関ラボ。

SQLiカテゴリでは「UNION攻撃」「エラーベース抽出」「ブラインド（ブール値ベース／時間ベース）」「HTTPヘッダ経由の注入（Cookie、User-Agentなど）」「二次注入」「WAFバイパス」といった各テーマごとに、この3段階が用意されている構成になっている。本教科書のこれまでの章（UNION＝第2章、ブラインド＝第3章、WAF＝第5章、二次注入＝第6章）と1対1で対応させながら進めると理解が深まる。

各トピックのページ構成は「概念解説（本文）→ 具体的な攻撃手法ごとの解説 → 該当する実践ラボへのリンク → 防御方法」という一貫した流れになっており、この教科書自体もこの構成を参考にしている。ラボの攻略には無料版の**Burp Suite Community Edition**で十分であり、公式サイトでも「The best manual tools to start web security testing.」（手動でのWebセキュリティテストを始めるための最良のツール群）と位置づけられている。Community Editionにはリクエストの傍受・改変を行うProxy機能と、リクエストを手動で繰り返し送信・微調整できるRepeater機能が含まれており、SQLiラボの多くはこの2つの機能だけで完結する（自動スキャナ機能はProエディション限定）。

#### 防御方法についての言及

このページはSQLi対策の核心を次の一文で明快にまとめている。

> Most instances of SQL injection can be prevented by using parameterized queries (also known as prepared statements) instead of string concatenation within the query.

（ほとんどのSQLインジェクションは、クエリ内での文字列結合の代わりにパラメータ化クエリ（プリペアドステートメントとも呼ばれる）を使うことで防止できる。）

パラメータ化クエリでは、SQL文のテンプレート（構文の骨格）をDBMSに事前に送ってコンパイルさせ、その後でユーザー入力を「値」としてのみバインド（割り当て）する。この方式では、DBMSのパーサがユーザー入力を構文の一部として再解釈する余地が原理的に存在しない――なぜなら、構文木の構築（パース）がユーザー入力を見る前にすでに完了しているためである。これは第4章以降で扱った防御論の要点であり、Academyのページでも同じ結論に到達している。

> 出典: SQL injection — https://portswigger.net/web-security/sql-injection

### sqli-labs — セルフホスト型の段階的ローカルラボ

#### 概要

[sqli-labs](https://github.com/Audi-1/sqli-labs)（開発者: Audi-1、GitHub上で5,800以上のスターを獲得）は、自分のマシン（またはVM）上に構築して使う、PHP + MySQLベースのSQLi専用演習環境である。Web Security Academyがクラウド上のホスト型ラボであるのに対し、sqli-labsは**完全にローカルで動作する**点が最大の違いであり、ネットワーク越しの応答遅延やレートリミットを気にせず、time-based blindのような遅延に敏感な技法をじっくり検証できる利点がある。

> 出典: sqli-labs (Audi-1) — https://github.com/Audi-1/sqli-labs

#### ラボ構成

sqli-labsは番号付きの課題（Less-1、Less-2、…）として構成されており、合計で**65個のレッスン**が用意されている。カバーされる技法は多岐にわたる。

- **エラーベース注入**: 文字列型・数値型パラメータそれぞれに対するUNION SELECT攻撃、ダブルクエリインジェクション（`extractvalue()` や `updatexml()` のようなXPath構文エラーを利用してDBMSのエラーメッセージにデータを埋め込ませる手法。第2章で扱ったエラーベース抽出の実践版）
- **ブラインドインジェクション**: ブール値ベース（真偽の応答差分から推測）、時間ベース（`SLEEP()` による遅延の有無から推測）
- **クエリタイプ別の注入**: `SELECT` 文だけでなく `UPDATE` 文、`INSERT` 文への注入（例えばユーザー登録フォームのニックネーム欄がそのままUPDATE文に結合されているケース）
- **HTTPヘッダー経由の注入**: `Referer`、`User-Agent`、`Cookie` ヘッダーの値が検証なしにSQL文へ組み込まれるケースを再現。アプリケーションログ機能などでよく見られる実装ミスに対応する
- **二次注入（Second-order injection）**: 一度DBに保存された入力が、別のクエリ実行時に無害化されずに再利用されてしまうパターン（第6章の内容と対応）
- **スタック型SQLインジェクション（Stacked queries）**: `;` で区切って複数のSQL文を同時実行させる手法
- **WAF／フィルタバイパス技術**: `addslashes()` 関数（`'` や `"` の前に `\` を自動挿入してエスケープするPHPの標準関数）の突破、および特定条件下での `mysql_real_escape_string()`（文字セットを考慮した専用のエスケープ関数）の回避

`addslashes()` の突破は特に「なぜそうなるのか」の理解が重要である。`addslashes()` はマルチバイト文字セット（GBKなど）を考慮しない単純なバイトレベルのエスケープであるため、`%bf%27` のような2バイト文字の後半バイトと単引用符が組み合わさると、MySQL側では「1つのマルチバイト文字＋壊れたバックスラッシュ」ではなく「有効なマルチバイト文字＋独立した単引用符」として再解釈されてしまうことがある。これはエスケープ処理がアプリケーション層の文字コード認識とDBMS側の文字コード解釈のズレを突く、古典的だが今も通用するバイパス手法である。

Less-54以降は模範解答が付いていない**スキル検証用チャレンジセクション**として設計されており、GET方式・POST方式の両方のシナリオに対応している。

#### セットアップ手順

sqli-labsを動かすには以下の環境が必要である。

- Apache（Webサーバー）
- MySQL（データベース）
- PHP（サーバーサイド処理系。バージョンによっては非推奨の `mysql_*` 系関数を使う実装のため、PHP 5.x系や互換レイヤーが必要になる場合がある点に注意）

```bash
# 1. リポジトリを Apache のドキュメントルートに展開
git clone https://github.com/Audi-1/sqli-labs.git /var/www/sqli-labs

# 2. sql-connections/db-creds.inc を編集し、
#    ローカル環境のMySQL認証情報（ユーザー名・パスワード）に書き換える

# 3. ブラウザで sql-labs フォルダの index.html にアクセス

# 4. 画面上の setup/reset DB リンクをクリックし、
#    演習用データベースとテーブルを初期化する
```

DBの初期化（setup/resetDB）を最初に必ず実行する必要がある点が重要で、これを忘れるとレッスンが正しく動作しない（テーブルが存在せずPHPがエラーを返す）。環境構築にDocker等の公式イメージが同梱されているわけではないため、XAMPP/MAMPやLAMPスタックの手動構築、あるいは有志が作成したDockerfileを利用するのが実務上一般的な進め方である。

> 出典: sqli-labs (Audi-1) — https://github.com/Audi-1/sqli-labs

#### 学習上の位置づけ

sqli-labsの強みは、**PHPソースコードそのものを自分の手元で読める**ことにある。Web Security Academyのラボはブラックボックスとして提供されるが、sqli-labsは各Lessフォルダの中にある`.php`ファイルを直接開けば、クエリがどう組み立てられているか（文字列結合の実装そのもの）をソースレベルで確認できる。「なぜこのペイロードが刺さるのか」をブラックボックス的な推測ではなくホワイトボックスで裏付けたいときに最適な教材であり、第2〜3章で学んだ理論とソースコードを突き合わせる復習に向いている。またネットワーク遅延がない環境で動くため、time-basedブラインドの`SLEEP()`秒数チューニングなど、遅延ベースの技法をノイズなく練習できる点も実務上有用である。

### TryHackMe SQL Injectionルーム — ガイド付き初心者向けパス

#### 概要

[TryHackMe](https://tryhackme.com/room/sqli) の「SQL Injection」ルームは、データベースやSQLの基礎知識がまだ十分でない学習者を主な対象とした、ガイド付き（一問ずつ解説を読みながら進める形式）の入門ルームである。WebSearchによる要約情報によれば、ルームの概要は次の通りである。

> In this room, you'll learn what databases are, what SQL is with some basic SQL commands, how to detect SQL vulnerabilities, how to exploit SQLi vulnerabilities and, as a developer, how you can protect yourself against SQL Injection.

（このルームでは、データベースとは何か、SQLとは何か・基本的なSQLコマンド、SQLの脆弱性の見つけ方、SQLiの悪用方法、そして開発者としての防御方法を学ぶ。）

> ⚠️ **未取得の資料**: TryHackMeのルームページ本体は自動取得の際にHTTP 429（Too Many Requests、短時間の連続アクセスに対するレート制限）が返され、直接取得できませんでした。以下はWebSearchで得られた複数の二次情報（Walkthrough記事等）に基づく要約です。正確な最新のタスク構成・料金体系はご自身で直接ご覧ください: https://tryhackme.com/room/sqli

#### 構成とレベル設計

このルームは、SQLiカテゴリの中でも「初めてSQLiに触れる」層を明確に意識した構成になっている。

1. **導入タスク（タスク1〜4）**: 読み物中心。データベースの基本概念、SQL文の基礎構文（`SELECT`、`WHERE` など）、SQLiがなぜ発生するのかという原理的な説明にあてられている。
2. **検出手法の解説**: 単引用符 (`'`) を入力して意図的にエラーを発生させ、レスポンスの変化（エラーメッセージの有無、画面表示の崩れなど）から脆弱性の兆候を掴む、という最も基本的な検出フローを学ぶ。
3. **In-band / Out-of-band / Blind の3分類**: 攻撃結果をどのチャネルで受け取るかによる分類を導入する。
   - **In-band SQLi**: 攻撃に使ったのと同じ通信チャネル（同じHTTPレスポンス）上で直接データを取得する（UNION攻撃やエラーベース抽出がこれに該当）。
   - **Out-of-band SQLi**: 別の通信チャネル（DNSクエリやHTTPコールバックなど）を使ってデータを外部に持ち出す手法（第3章で扱ったOOB技法に対応）。
   - **Blind SQLi**: 直接的なフィードバックがない状況で、タイミングやエラーの有無といった間接的な兆候から情報を推測する（第3章のブラインド技法に対応）。
4. **実践ラボ（タスク9）**: 4段階のライブラボが用意されており、UNION抽出・ログインバイパス・ブール値ベースブラインド・時間ベースブラインドという4つの技法を、1レベルにつき1技法ずつ切り分けて練習する構成になっている。入力に応じて実際に発行されるSQLクエリがその場で画面に表示される仕組みがあり、「自分の入力がクエリのどこに、どう挿入されたか」を視覚的に確認しながら学べる点が初心者向けとして評価されている。

TryHackMeはFree（無料）プランとPremiumプラン（サブスクリプション課金）の2階層モデルを採る教育プラットフォームであり、多くの入門ルームはFreeプランでもアクセス可能である。個々のマシン（脆弱なVM環境）にブラウザ経由でVPN接続、またはブラウザ内蔵の仮想デスクトップ（AttackBox）を使ってアクセスする方式が一般的だが、ルームによっては一部タスクや高度なマシンがPremium限定になっている場合があるため、正確な現在の料金・アクセス条件は上記URLから直接確認することを推奨する。

3. **sqli-labs**をローカルに構築し、Academyでは見えないPHPソースコードを実際に読みながら、なぜそのペイロードが通るのかをホワイトボックスで検証する。特にtime-basedブラインドやHTTPヘッダー経由の注入、二次注入といった「本番環境に近い実装ミス」の再現に向いている。

3つのプラットフォームはいずれも無償（またはFreeプランで大部分利用可能）でありながら、それぞれ異なる学習体験（ガイド付き入門／実務品質のブラックボックスラボ／ソース閲覧可能なホワイトボックスラボ）を提供する。次節では、これらのラボ演習と並行して活用すべき継続学習のための情報源（ブログ、CTF、脆弱性情報のフィード等）を扱う。
