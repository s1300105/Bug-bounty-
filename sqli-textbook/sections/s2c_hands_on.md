## in-band系ハンズオンラボ

前節までで、in-band SQLi(攻撃者がリクエストを送り、同じチャネル（HTTPレスポンス）で結果を直接受け取れる注入形態)のうち、UNIONベースとエラーベースの原理を扱った。本節ではそれを実際に手を動かして確認するための2つの定番教材——セルフホスト型の`sqli-labs`と、ガイド付きオンラインコースの HTB Academy「SQL Injection Fundamentals」——を取り上げ、それぞれのラボ構成と、そこで踏む具体的なステップを解説する。座学だけでは「なぜこのペイロードで動くのか」が身につかない。実機で「壊してみて」初めて、パーサがどう解釈しているかの直感が育つ。

### なぜハンズオン教材が必要か

UNIONベースSQLiが刺さるには、(1) 注入点が既存のSELECT文の結果セットに影響を与えられる、(2) `UNION SELECT`で結合した列数と型がオリジナルのクエリと一致する、という2条件が必要になる。エラーベースSQLiは逆に、アプリケーションが例外を握りつぶさずDBエラーメッセージをそのまま(あるいは形を変えて)画面に返してしまう実装のとき、そのエラー文字列自体をデータ抽出のチャネルとして使う手法である。どちらも「読んで理解した」つもりでも、実際に列数を1つずつ増減させて`ORDER BY`のエラー有無を観察したり、`extractvalue()`が投げる例外メッセージの中に自分が仕込んだサブクエリの結果が現れる瞬間を見ないと、手が覚えない。以下の2教材はまさにこの「手が覚える」段階を担う。

### 教材1: sqli-labs (Audi-1)

> 出典: GitHub - Audi-1/sqli-labs — https://github.com/Audi-1/sqli-labs

`sqli-labs`は、SQLインジェクションを学ぶための自己ホスト型PHP+MySQLの脆弱アプリケーション集であり、GitHub上で5.8kスター・1.6kフォークを持つ、この分野で最も広く使われている演習環境の一つである。作者はAudi-1(別名)。

#### ラボの全体構成

- **Less-1 〜 Less-53**: 段階的に難易度・注入パターンを変えた学習用ラボ
- **Less-54 〜 Less-61**: 習得した知識を試す「スキル検証」用チャレンジレッスン

この段階構成自体が教育設計として重要である。同じ脆弱性でも、GETパラメータでの数値型注入(`Less-1`系)から始まり、文字列型(シングルクォート閉じが必要)、次にPOSTベース、Cookie/HTTPヘッダ(User-Agent, Referer)経由、二次注入(Second Order)、そしてWAFフィルタが挟まる回とステップアップしていく構成になっている。この順序自体が「実際の脆弱アプリでSQLiを探すときに、どの箇所を疑うべきか」というチェックリストにもなっている。

#### カバーされる攻撃カテゴリ

sqli-labsのREADMEおよびラボ構成が扱う攻撃タイプは大きく以下に分類される。

1. **Error Based Injection**
   - Union Select(文字列型・整数型の双方)
   - Double Injection Based(`extractvalue()`/`updatexml()`のような、XPath構文エラーを誘発してエラーメッセージにデータを漏らす手法。詳細は本章前節を参照)
2. **Blind Injection**
   - Boolean Based(真偽の違いをレスポンスの差分から読み取る)
   - Time Based(`SLEEP()`などで応答時間の差から真偽を読み取る)
3. **その他の注入形態**
   - Update/Insert Query Injection(SELECTではなくUPDATE/INSERT文への注入。列挙よりも改ざん・権限昇格に近い実害へ直結しやすい)
   - Header Injection(Referer / User-Agent / Cookieヘッダを注入点として使う。ログ機能やUA判定処理がSQLに未サニタイズで連結される実装で刺さる)
   - Second Order Injection(1回目のリクエストでDBに保存された値が、2回目以降の別処理でSQL文に組み込まれて発火する。入力時点のバリデーションだけでは防げない典型例)
   - Stacked SQL Injection(セミコロンで文を区切って複数クエリを一括発行させる。MySQLのPHP `mysqli`ドライバはデフォルトでは複数クエリ実行を許可しないため、成立するには`mysqli_multi_query()`のような明示的な実装が必要——これは「なぜ動くか」の典型例で、ドライバ/API側の挙動を確認する癖をつけるべき箇所)
4. **WAF/フィルタ回避技術**
   - ブラックリスト方式のフィルタ(特定キーワードを弾くだけの実装)のバイパス
   - `addslashes()`や`mysql_real_escape_string()`のような、シングルクォートのみをエスケープするサニタイズ処理の回避(例: GBKなどマルチバイト文字セットを使ったワイドバイトインジェクションで、バックスラッシュを「食わせて」無効化する手法が典型)

#### 環境構築手順

READMEに記載された手順は以下の通りである。

```text
1. リポジトリを /var/www 配下(あるいは任意のWebルート)に展開/クローンする
2. sql-connections フォルダ内の db-creds.inc を編集し、
   MySQL接続情報を設定する(デフォルトは root:toor)
3. ブラウザで setup/resetDB.php (setup/resetDB) にアクセスする
4. データベースが自動作成・初期化される
```

この設計のポイントは「DBスキーマを毎回自動リセットできる」ことにある。演習中にラボのデータを壊してしまっても`resetDB`で元に戻せるため、破壊的なペイロード(DROP文やUPDATE文を伴う攻撃)を安心して試せる。実運用のペンテストでは決してできないような「本番相当のDBを壊す系」の攻撃(Insert/Update Injectionなど)を安全に体験できるのは、このラボ最大の価値である。

#### 代表的な進め方(一般知識による補足)

> (以下は、sqli-labsの一般的な使われ方について、公開情報・実務知識に基づく補足である)

sqli-labsの最初のいくつかの回(Less-1〜Less-4相当)は、URLパラメータ`?id=`に対する典型的なGETベースの注入点を練習する構成になっている。たとえば文字列型でシングルクォート囲みの注入点では、まず

```
?id=1'
```

のような単一クォートを送ってDBエラーやページ崩れが起きるかを確認し(構文を壊せるかの確認=注入点の存在確認)、次に

```
?id=1' order by 3-- -
```

で列数を特定し(`order by N`でエラーが出なくなる最大のNが列数)、

```
?id=-1' union select 1,2,3-- -
```

で結果セットのどの列がレスポンス上に表示されているかを可視化し、最後にその表示位置に`database()`や`table_name`、`column_name`、`group_concat(...)`といった情報スキーマ由来のクエリを差し込んでDB名・テーブル名・カラム名・データを段階的に抽出していく、という流れを踏む。この「クォートで壊す→列数を確定する→表示列を特定する→情報を差し込む」という4ステップの型は、UNIONベースSQLiの標準的な攻略手順そのものであり、sqli-labsはこの型を反復練習するために最適化された構成になっている。

### 教材2: HTB Academy「SQL Injection Fundamentals」

> 出典: HTB Academy — SQL Injection Fundamentals(コースプレビュー) — https://academy.hackthebox.com/course/preview/sql-injection-fundamentals

こちらはHack The Box Academyが提供する、ガイド付き・演習環境同梱のオンラインコースである。sqli-labsが「素のラボを自分で操作して学ぶ」型なのに対し、こちらは「講義本文を読みながら、埋め込まれた実習環境で手を動かす」型であり、初学〜中級者が体系立てて基礎から積み上げるのに向いている。

#### コース概要

- 難易度: Medium(中程度) — HTB Academyの難易度表記では、この分野に初めて触れる層より一段上、ある程度Web/DBの前提知識がある層を想定したレベル付けになっている
- セクション数: 17
- 評価: 5点満点中4.82(公開時点)
- 作成者: 21y4d

受講にあたり以下が前提とされている。

#### 学習目標として明示されている到達点

- データベース管理システム(DBMS)の動作原理の理解
- MySQLにおける基本的なクエリ操作の習得
- SQLi脆弱性の検出・悪用手法の習得
- クエリロジックの改変による認証回避
- UNIONベースSQLiによるデータベース内データの抽出技術
- サーバ上のファイルの読み書き(`LOAD_FILE()` / `INTO OUTFILE`)
- Webシェル設置によるリモートアクセス確立
- 脆弱性の緩和・防止策の理解

「ファイルの読み書き」から「Webシェル設置」までを到達点に含めている点は、sqli-labsが基本的に列挙(情報の読み取り)中心であるのに対し、HTB Academyのコースはさらに一歩進んで、UNIONベースSQLiがRCE(リモートコード実行)まで到達しうることを明示的にカリキュラムに組み込んでいる点で対照的である。MySQLの`SELECT ... INTO OUTFILE`は、`secure_file_priv`設定が空文字列または該当ディレクトリを許可している場合に限り、Webルート配下へファイル(典型的にはPHP Webシェル)を書き込めてしまう。これはMySQLのバージョンや`my.cnf`の設定に強く依存する機能であり、デフォルトで`secure_file_priv`が厳格化された近年のMySQL/MariaDBでは単純には通らないことが多い点に注意したい。ラボ環境ではこの設定があえて緩められていることが一般的である。

### 2教材の使い分け方(学習設計としての補足)

> (以下は一般知識に基づく学習設計上の補足である)

この2つは競合というより補完関係にある。HTB Academyのコースで「DBの基礎からUNION句・情報スキーマ列挙・対策」までの概念的な骨格と手順の型を身につけ、その後にsqli-labsのLess-1から順に手を動かすと、コースで学んだ「クォートで壊す→列数確定→列挙」の型を、Header InjectionやSecond Order Injection、WAFバイパスといったより実戦的な変化球に対して繰り返し適用する訓練になる。逆に、いきなりsqli-labsから始めると、なぜ`order by`でエラーが起きるのか、なぜ`union select`の列数を合わせる必要があるのか(=各行のカラム型・カラム数が結果セット全体で一致していなければならないというSQLの型システムの制約)といった「なぜ」の部分でつまずきやすい。本章の理論パートと合わせて、この順序で取り組むことを推奨する。

### 本節のまとめ

- `sqli-labs`は61個の段階的ラボを持つセルフホスト型演習環境で、Error/Union/Blind/Update-Insert/Header/Second Order/Stacked SQLi、およびWAFバイパスまでを一通り体験できる。`resetDB`によるスキーマ初期化機能により、破壊的なペイロードも安全に試行できる。
- HTB Academyの「SQL Injection Fundamentals」は17セクション構成のガイド付きコースで、DBの基礎からUNIONベースSQLi、ファイル読み書きを経てWebシェル設置に至るまでを段階的にカバーし、対策(緩和策)まで含めて学べる。
- どちらもUNIONベースSQLiの核心である「クォートで壊す→列数を確定する→表示列を特定する→情報スキーマで列挙する」という手順を体に染み込ませることを目的としており、この型は本章で扱う攻撃全般の土台になる。
