# 序章：この分野をどう学ぶか

## なぜ「デシリアライゼーション」と「SSTI」を一冊にまとめるのか

一見すると、オブジェクトのシリアライズ形式を扱うデシリアライゼーションと、テンプレートエンジンの評価機構を突くSSTIは別種の脆弱性に見える。しかし両者は**「信頼できない入力が、データとして扱われるべき場所でコードとして解釈される」**という同一の病理を共有している。デシリアライゼーションでは復元処理が意図せずガジェット（既存クラスのメソッド連鎖）を発火させ、SSTIではテンプレート評価器が攻撃者の式をサーバ側で実行する。どちらも到達点は **RCE（リモートコード実行）** であり、バグバウンティにおける最高深刻度帯の中心的テーマである。

この2つを貫く共通の思考様式が、本書の背骨をなす3つの概念だ。

- **ガジェット / チェーン**：単体では無害な処理を、攻撃者が望む順序で連鎖させて任意コード実行に至らせる考え方。
- **マジックメソッド / 自動評価点**：`__wakeup` / `readObject` / `__reduce__` / テンプレートの `{{ }}` のように、「入力を受け取ると自動的に呼ばれる／評価される」入口。
- **サンドボックス脱出**：制限された実行環境（Jinja2のサンドボックス、テンプレートの許可関数など）から、汎用的なコード実行フローへ復帰する技術。

この枠組みを先に固めておくと、言語・エンジンごとの各論が「同じ骨格の変奏」として一気に理解できる。

## 前提知識と対象読者

本書は、Webセキュリティの素朴な基礎（HTTP、リクエスト改ざん、基本的な脆弱性クラス）を既知とする**中〜上級者**を対象とする。各章は原典を要約するだけでなく、「なぜその処理が危険なのか」をソースコードや実行フローのレベルまで掘り下げる。特に第3章（Java）と第8章（Jinja2）は本分野の実力差が出る核心であり、時間を投じる価値がある。

## 学習の進め方（ロードマップの推奨）

1. **まず手を動かす**：PortSwigger の Insecure deserialization ラボ →  SSTI ラボを、許可された環境で完走する。PHPの人間可読なserialize文字列でPOPチェーンの直感を得るのが最短。
2. **Javaに投資する（最重要）**：CommonsCollections1 の reflection フローを図で説明できるようにする。ここが「他人のペイロードを流すだけ」から「新規チェーンを作れる」への飛躍点。
3. **ツールを卒業する**：phpggc / ysoserial.net / SSTImap / tplmap を走らせ、生成物のバイト列を `pickletools` / `javap` / デコーダで**手で読む**。
4. **サンドボックス脱出を極める**：Jinja2のフィルタ回避（`.` / `_` / `[]` 禁止環境）を、`request` オブジェクト経由で突破できるようにする。
5. **実戦とAI接続**：HackerOne実報告の型を学び、pickle/MLモデルRCE（Hugging Face等）というホットな領域とAIセキュリティを統合する。

## 倫理と法

本書のツール・技術はすべて**許可された対象**（自分の検証環境、正式なバグバウンティスコープ、教育用ラボ）でのみ用いること。脆弱性は「デシリアライズする側／テンプレートを評価する側」の実装にあり、攻撃技術の理解は防御・検知・安全な設計を組み立てるためにこそ役立つ。本書は一貫して**防御目的**で記述し、実在サービスへの無許可検証や破壊的手順は扱わない。

それでは、第1章から始めよう。
