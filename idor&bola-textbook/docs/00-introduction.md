# 序章 はじめに

## 本書が扱う領域と、なぜ「極める」価値があるのか

本書のテーマは、**Broken Access Control（アクセス制御の不備）** を中核に、その3つの現れ方を統合的に扱うことです。

- **IDOR / BOLA（オブジェクトレベル認可の不備）** ― 他ユーザーのデータ（オブジェクト単位）へアクセスできてしまう水平権限の欠落。Web では IDOR、API では BOLA と呼ばれ、実体は同じです。
- **BFLA（機能レベル認可の不備）** ― 管理者機能など、本来上位ロールにしか許されない**機能**を呼べてしまう垂直権限昇格。
- **BOPLA / Mass Assignment（プロパティレベル認可の不備）** ― `isAdmin=true` のように、本来書き換え不能な**プロパティ**を送り込めてしまう欠落。

この3層（オブジェクト／機能／プロパティ）で「認可の欠落箇所」を漏れなく捉えるのが、本書の背骨です。さらに、認可の穴と地続きにある **ビジネスロジック脆弱性**（価格・数量操作、ワークフロー順序の破壊、状態機械の破壊）と、それを時間軸で破る **レースコンディション**、境界の1欠落が全顧客に波及する **マルチテナンシー** を扱います。

なぜ「極める」価値があるのか。理由は単純です。**この領域は自動スキャナが原理的に苦手**だからです。正常・認証済み・整形済みのリクエストが正常レスポンスを返すため、シグネチャもエラーもログ異常も出ません。ゆえに人間の文脈理解と体系的アプローチが決定的に効きます。OWASP Top 10 では Broken Access Control が **A01（首位）**、OWASP API Security Top 10 では **BOLA（API1）が2019年の初版から一貫して#1** です。バグバウンティで最大級の報奨カテゴリでありながら、勝負どころが「アプリ固有の権限モデル・状態遷移の理解」と「創造性を再現可能な型に落とすこと」にある ― これが本書の存在理由です。

## 想定読者と前提知識

- HTTP／Cookie／セッションの基礎、Burp Suite などのプロキシの基本操作を知っている中〜上級者を想定します。
- 既に IDOR を「なんとなく」実践している方が、**属人的な勘を網羅的な手順書へ変換する**段階に最適化しています。
- 各節は「読者が原文を読まずとも要点を理解できる詳しさ」で書かれていますが、**原典リンクを開いて手を動かすこと**を前提にしています。

## 本書の構成（読み進め方）

本書はロードマップの10レベルに対応する10章で構成されます。

1. **第1〜2章（土台と型化）**：アクセス制御の語彙・分類・OWASPの地図を固め、IDOR/BOLA を「勘」から「網羅的手順」へ。ここを1〜2週間で走り抜けるのが推奨です。
2. **第3〜4章（主戦場）**：401/403突破のフルマトリクスと、スキャナが見つけられないビジネスロジック・認証フローの欠陥。ここが深掘りの中心。
3. **第5〜7章（攻撃面の拡張）**：レースコンディション（single-packet attack）、cross-tenant、API/GraphQL 特有の攻撃面。
4. **第8章（半自動化）**：Autorize / AuthMatrix で2セッション比較・多ロール総当りを回す。
5. **第9〜10章（実戦と型の確立）**：実報告を大量にインプットし、自分のプレイブック（マッピング→A-B/A-B-Aテスト→バイパス総当り→チェーン化）をテンプレ化する。

## 倫理と法令遵守（必読）

本資料は、**許諾されたバグバウンティ／脆弱性診断の範囲でのみ**活用してください。とりわけ本書が扱う脆弱性クラスは、検証が**他ユーザー・他テナントの実データに影響し得る**という固有の危うさを持ちます。テストは**テスト用アカウント・スコープ内資産**に限定し、対象プログラムのスコープとルールを厳守し、責任ある開示を徹底してください。破壊的な手順や、実在サービスへの無許可検証の完成形ペイロードは本書には含めません。
