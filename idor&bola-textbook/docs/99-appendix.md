## 付録C：用語集

- **アクセス制御（Access Control）**：認証済みの主体が、あるリソース・機能に対して許可された操作のみを行えるよう制限する仕組み。**認証（誰か）** と区別される **認可（何をしてよいか）** の実装。
- **IDOR（Insecure Direct Object Reference）**：ユーザーが操作可能な参照（ID等）を書き換えることで、他者のオブジェクトにアクセスできてしまう欠陥。API 文脈では **BOLA** と呼ぶ。
- **BOLA（Broken Object Level Authorization）**：OWASP API Security Top 10 の API1。オブジェクト単位の認可欠落。IDOR と実体は同一。
- **BFLA（Broken Function Level Authorization）**：機能単位の認可欠落＝垂直権限昇格。管理者機能を一般ユーザーが呼べる等。
- **BOPLA / Mass Assignment**：プロパティ単位の認可欠落。`isAdmin` など本来書き換え不能な属性を送り込めてしまう。
- **垂直権限昇格 / 水平権限昇格**：前者はより高い権限（管理者）へ、後者は同格の別ユーザーの資源へ、という越境。
- **RBAC / ABAC**：ロールベース／属性ベースのアクセス制御モデル。
- **2アカウント法**：低権限アカウントAのリクエストを、別アカウントBのセッションで再送し、レスポンス差分から認可欠落を判定する検出手法。**A-B / A-B-A テスト**として体系化される。
- **forced browsing**：UIに現れない管理URL・機能を直接推測アクセスして権限制御の欠落を突く手法。
- **ビジネスロジック脆弱性**：アプリが意図した機能の前提（数量は正、順序はこの通り等）を破ることで生じる欠陥。スキャナが原理的に見つけにくい。
- **レースコンディション / limit-overrun / TOCTOU**：並行リクエストで「検査と実行の間（Time-Of-Check to Time-Of-Use）」を突き、回数制限や残高チェックを破る技法。
- **single-packet attack**：James Kettle が示した、複数リクエストを1つのTCPパケットで同時到達させ、ネットワーク揺らぎを排して局所的にレースを起こす手法。
- **マルチテナンシー / cross-tenant**：1つのシステムを複数顧客（テナント）で共有する構成と、そのテナント境界を越えてデータにアクセスできてしまう欠陥。
- **GraphQL introspection / alias / batching**：スキーマ自己記述機能／同一フィールドの多重問い合わせ別名／複数クエリの一括送信。IDORの一括化やレート制限回避に悪用され得る。
- **Autorize / AuthMatrix / Auth Analyzer**：低権限セッションでのリクエスト自動リプレイや、ロール×リクエストの権限マトリクス検証を半自動化する Burp 拡張。
