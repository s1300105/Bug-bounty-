## Beyond XSS 概説（無料オンライン書籍の全体像）

XSS（クロスサイトスクリプティング）を体系的に学ぼうとすると、多くの人は「`<script>alert(1)</script>` が実行できたら勝ち」という単純なイメージで止まってしまいます。しかし実際のフロントエンドセキュリティは、XSS を入り口にしてはるかに広い領域へ続いています。台湾のフロントエンドエンジニアであり CTF プレイヤーでもある Huli（アカウント名 `aszx87410`、ブログ https://blog.huli.tw/ ）が無料公開している電子書籍シリーズ **「Beyond XSS: フロントエンドセキュリティ系列」**（英語版・日本語版とも無料で全文公開）は、この「XSS の先にある世界」を一冊にまとめた資料です。本書（この教科書）が扱う個々のトピック――サニタイズ回避、CSP バイパス、mXSS、プロトタイプ汚染、DOM Clobbering、CSRF、XSLeaks など――の多くは、Beyond XSS が最初に体系立てて紹介したものであり、以降の章を読み進める上での「地図」として非常に有用です。ここでは Beyond XSS 全体の構成と、著者がどのような問題意識でこのシリーズを書いたのかを紹介し、読者がこの教科書の残りの章をどう位置づけて読めばよいかを示します。

### Beyond XSS とは何か

Beyond XSS は英語版（`https://aszx87410.github.io/beyond-xss/en/`）と日本語版（`https://aszx87410.github.io/beyond-xss/ja/`）が公開されている、フロントエンドセキュリティに特化した連載記事群です。両言語版とも構成は同一で、全体は次の5章に分かれています。

1. **第1章: XSS を起点に**（原題: Starting with XSS）
   - ブラウザのセキュリティモデル
   - XSS の基礎と、そこからさらに踏み込んだ理解
   - `javascript:` プロトコルにまつわる脆弱性
2. **第2章: XSS の防御と回避**（原題: Defense and Bypass for XSS）
   - サニタイズ、CSP（Content Security Policy）による影響範囲の縮小
   - Trusted Types と組み込みサニタイザー API（Sanitizer API）
   - よくある CSP バイパス手法と Mutation XSS（mXSS）
   - Universal XSS（UXSS）
3. **第3章: JavaScript を使わない攻撃**（原題: Attacks Without JavaScript）
   - プロトタイプ汚染（Prototype Pollution）と DOM Clobbering
   - クライアントサイドテンプレートインジェクション（CSTI）
   - CSS インジェクション、HTML インジェクション
4. **第4章: サイトをまたぐ攻撃**（原題: Cross-site Attacks）
   - 同一オリジンポリシーと「サイト」概念の違い
   - CORS の仕組みと脆弱性
   - CSRF、SameSite Cookie
   - サブドメインの悪用、Cookie Bombing
5. **第5章: その他の興味深いトピック**（原題: Other Interesting Topics）
   - クリックジャッキング、MIME スニッフィング
   - サプライチェーン攻撃
   - Web3 関連のセキュリティ問題
   - XSLeaks（サイドチャネル系の情報漏洩攻撃）

### 著者の問題意識: 「XSS しか知らない」ことの危険性

Huli は日本語版・英語版いずれのイントロダクションでも、フロントエンド開発者の多くが「XSS のことしか知らず、それ以外は何も知らない（`only know about XSS, and know nothing else`）」という状況に警鐘を鳴らしています。これは煽り文句ではなく、著者自身の実体験に基づく指摘です。著者はセキュリティの仕事に足を踏み入れてから、自分がそれまで触れてきたフロントエンド技術の「8割」が、実はセキュリティ観点で見ると未知の領域だったと述べています。

この構造は、通常のアプリケーション開発の学び方と根本的に異なります。開発者は「動くコードを書く」ために必要な知識を積み上げていきますが、その過程で「なぜこの API は制限されているのか」「なぜブラウザはこの動作を許さないのか」という*境界条件*を意識する機会はほとんどありません。ところがセキュリティの世界では、まさにその境界条件――ブラウザやサーバーが「許可していない」はずの操作を、実装の隙間を突いてすり抜ける方法――こそが攻撃面になります。Beyond XSS はこの見えない領域に光を当てることを目的として書かれています。

著者は本シリーズの総括ページ（summary）で、フロントエンドセキュリティを「宇宙（universe）」に例えています。XSS はその宇宙の中で最も目立つ「恒星」のような存在であり、遠くからでも見える代表的な脅威です。しかし宇宙にはそれ以外にも無数の「小さな惑星や恒星」――CSRF、プロトタイプ汚染、XSLeaks、サプライチェーン攻撃など――が存在し続けており、それらは XSS ほど有名ではないものの、実際の攻撃や CTF、バグバウンティの現場では頻繁に登場します。

### なぜ「XSS の教科書」の中で Beyond XSS を紹介するのか

この教科書（本書）自体も XSS を主題としていますが、XSS という脆弱性は単独で存在しているわけではありません。以下の3つの理由から、Beyond XSS 全体の地図を早い段階で押さえておくことには実務上の意味があります。

**第一に、XSS の「防御」と「防御回避」は、そのまま第2章以降の独立した専門領域になっているためです。** 例えば CSP は XSS の被害を軽減するための代表的な防御機構ですが、CSP 自体にも数多くのバイパス手法があり、Trusted Types や Sanitizer API のような比較的新しい防御機構にも独自の回避テクニックが存在します。mXSS（Mutation XSS）はブラウザの HTML パーサーがサニタイズ後に文字列を「正規化」する過程で、一見安全に見えた文字列が危険な形に変異する現象であり、単に「タグをエスケープすればよい」という発想では防げません。これらは本書の中盤〜終盤の章で個別に深掘りしますが、その位置づけを理解するには、まず「XSS 対策には複数のレイヤーがあり、それぞれに固有の攻撃面がある」という全体像を知っておく必要があります。

**第二に、JavaScript の実行を伴わない攻撃（第3章の領域）が、しばしば XSS の入口や補助として使われるためです。** プロトタイプ汚染は、それ単体では画面に何かが表示されるわけではありませんが、アプリケーションの内部ロジックを歪め、結果として XSS に発展するケースが数多く報告されています。DOM Clobbering も同様に、`id` や `name` 属性を持つ HTML 要素がグローバル変数や DOM プロパティを「上書き」してしまう現象を悪用し、JavaScript の実行なしに `<script>` タグの読み込みを妨害したり、逆に意図しないコードパスを引き起こしたりします。これらは古典的な「reflected/stored XSS」の枠組みだけを学んだ読者には見落とされがちな攻撃経路です。

**第三に、XSS と隣接する「サイトをまたぐ攻撃」（第4章）や「サイドチャネル攻撃」（第5章の XSLeaks）は、しばしば XSS と組み合わせて初めて実害につながるためです。** 例えば、CSRF トークンを盗み出すために XSS を使う、あるいは XSS が使えない状況で XSLeaks を使ってユーザーの秘匿情報（ログイン状態、検索履歴の有無など)を一ビットずつ推測するといった手法は、いずれも脆弱性同士の連鎖（チェイン）としてバグバウンティレポートに頻出します。単一の脆弱性クラスだけを学んでいても、実際の攻撃シナリオを組み立てる力は身につきません。

### ブラウザのセキュリティモデルという「出発点」

Beyond XSS が第1章の冒頭に置いているのが「ブラウザのセキュリティモデル」の説明です。これは XSS そのものの技術ではありませんが、なぜ XSS がここまで深刻な脆弱性として扱われるのかを理解するための前提知識にあたります。

著者は、フロントエンドの実行環境が徹底して「ブラウザが提供する範囲」に閉じ込められていることを、3つの制限として整理しています。

1. **ローカルファイルへのアクセス禁止。** ウェブページ上の JavaScript は、ユーザーが `<input type="file">` などを通じて明示的に選択したファイル以外、ローカルディスク上のファイルを読み書きできません。`fetch('file:///etc/passwd')` のような呼び出しは、たとえコードとして書けても実行時にブロックされます。これは、悪意あるウェブサイトを開いただけでハードディスク上の SSH 鍵や設定ファイルが盗まれる事態を防ぐための、ブラウザの根本設計です。
2. **システム API 呼び出しの制限。** マイクやカメラへのアクセスのように、OS レベルの機能に触れる API は、ブラウザが明示的に提供し、かつユーザーが許可（パーミッションダイアログで同意）したものだけが使えます。ブラウザが対応するインターフェースを用意していない機能は、どれだけ JavaScript を工夫しても呼び出せません。
3. **他のオリジンのページへのアクセス禁止(同一オリジンポリシー、Same-Origin Policy）。** あるオリジン（スキーム・ホスト・ポートの組で決まる境界）で動いているスクリプトは、別オリジンのページの DOM やレスポンス内容を直接読み取ることができません。著者が挙げる具体例は分かりやすく、「`blog.huli.tw` 上で動くスクリプトが、同じブラウザで開いている Gmail のメール本文を読み取れてしまったら大惨事になる」という説明です。この原則があるからこそ、私たちは複数のタブで異なるサービスに同時にログインしていても安心していられます。

Chromium 系ブラウザではこの同一オリジンポリシーをプロセスレベルでさらに強化する「Site Isolation」という仕組みも導入されています。これは、異なるサイトのコンテンツを別々の OS プロセスに割り当てることで、たとえ JavaScript エンジン自体に脆弱性があっても、その影響を他サイトのデータ漏洩にまで波及させにくくする多層防御です。逆に言えば、ブラウザのレンダリングエンジンや JavaScript エンジン自体に重大な脆弱性(例えば著者が言及する CVE-2021-30632 のような V8 の脆弱性）が見つかった場合、この同一オリジンポリシーという「約束事」そのものを迂回され、任意コード実行(RCE)にまで発展するリスクがあります。CVE-2021-30632 は Google Chrome の V8 JavaScript エンジンに存在した Out-of-bounds write の脆弱性で、2021年に修正されました。この種の脆弱性は XSS とは別カテゴリ(ブラウザ自体のメモリ安全性の問題)ですが、「ブラウザが約束している境界を破る」という点で、フロントエンドセキュリティ全体の脅威モデルを理解する上で対比的に有用な例です。

> 出典: ブラウザのセキュリティモデル — https://aszx87410.github.io/beyond-xss/ja/ch1/browser-security-model/

XSS がなぜここまで深刻に扱われるのかは、このセキュリティモデルを踏まえると明確になります。XSS とは、本来「別オリジンのスクリプトは実行できない」はずのページ上で、攻撃者が用意した JavaScript を*そのページ自身のオリジンとして*実行させてしまう脆弱性です。つまり XSS は、同一オリジンポリシーという最も基本的な防御ラインを、ブラウザのバグではなくアプリケーション側の実装ミスによって内側から突破してしまう攻撃だと言えます。ブラウザがどれだけ堅牢にオリジン間の分離を実装していても、アプリケーションが「信頼すべきでない入力」をスクリプトとして実行してしまえば、その分離は意味をなさなくなります。この構造を理解しておくと、後続の章で扱う「反射型 XSS」「格納型 XSS」「DOM based XSS」といった分類が、単なる用語の違いではなく、「攻撃者のスクリプトがどの経路を通ってページのオリジン内に持ち込まれるか」という一貫した視点で整理できるようになります。

### この教科書の中での Beyond XSS の使い方

Beyond XSS は個々のトピックについて非常に実践的なコード例や PoC(概念実証)を多数含んでいますが、その分量は5章・18トピック以上にわたり、一冊のオンライン教科書として読み切るには相応の時間がかかります。本書(この教科書)では、Beyond XSS が扱うトピックのうち XSS に直接関係する部分――サニタイズ回避、CSP バイパス、mXSS、プロトタイプ汚染や DOM Clobbering が XSS に発展するケースなど――を、原理レベルまで掘り下げて個別の章で扱っていきます。読者は本セクションを「目次」として頭に入れておくことで、以降の章がフロントエンドセキュリティ全体のどの位置に該当するのかを見失わずに読み進めることができるはずです。

また、Beyond XSS の総括ページでは、シリーズを読み終えた読者向けに PortSwigger の Web Security Academy(無料のオンライン学習プラットフォームで、実際に手を動かして脆弱性を再現できるラボが多数用意されている)や、フロントエンドセキュリティを専門とする研究者7名の X(旧Twitter)アカウントが紹介されています。これは、書籍やブログ記事を読むだけでは実践的なスキルは身につかず、実際に手を動かして試行錯誤する環境と、最新の攻撃手法を追い続けるための情報源の両方が必要だという著者の考えを反映したものです。本書の以降の章でも、可能な限り一次資料(公式ドキュメント、CVE、研究者のブログや発表資料)を明記し、読者が自分の手でさらに深掘りできるようにしています。

### まとめ

- Beyond XSS は Huli(`aszx87410`)による無料公開のフロントエンドセキュリティ連載で、英語版・日本語版が公開されている。
- 全体は5章構成: (1) XSS を起点に、(2) XSS の防御と回避、(3) JavaScript を使わない攻撃、(4) サイトをまたぐ攻撃、(5) その他の興味深いトピック。
- 著者の核心的な主張は「多くのフロントエンド開発者は XSS しか知らず、それ以外の広大な領域を知らない」というものであり、フロントエンドセキュリティ全体を「宇宙」に例えている。
- 第1章冒頭のブラウザセキュリティモデル(ローカルファイルアクセス禁止、システム API 制限、同一オリジンポリシー)は、XSS がなぜ深刻な脆弱性なのかを理解するための前提であり、XSS はこの同一オリジンポリシーをアプリケーションの実装ミスを通じて内側から突破する攻撃だと整理できる。
- 本書はこの地図の中で、特に XSS に直結する部分(防御・回避、mXSS、プロトタイプ汚染や DOM Clobbering からの XSS への発展など)を原理レベルで深掘りしていく。
