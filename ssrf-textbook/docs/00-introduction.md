# 序章：本書の狙いと SSRF の全体像

## なぜ SSRF を「体系的に」学ぶのか

SSRF（Server-Side Request Forgery、サーバサイドリクエストフォージェリ）は、**「攻撃者が指定した宛先へ、サーバ自身にリクエストを送らせる」**脆弱性である。一見すると「サーバが URL を1本取得するだけ」の地味な挙動だが、その先には内部専用サービス、クラウドのメタデータエンドポイント、無認証の内部データストアといった「境界の内側」が広がっている。2019年の Capital One 侵害（1億人超の情報漏洩）が SSRF による AWS メタデータ到達から始まったことは、この脆弱性がクラウド時代にいかに致命的になり得るかを象徴している。

SSRF は「浅く」も「深く」も学べる脆弱性である。両者を分けるのは、本ロードマップが繰り返し強調する次の2点だ。

1. **URLパーサ差を突くフィルタ回避（第5章）** — 対策（denylist / allowlist / スキーム制限）を、パーサとリクエスタの解釈のズレ、代替IP表記、DNSリバインディング、リダイレクトなどで潜り抜ける技術。Orange Tsai の研究「A New Era of SSRF」が原点。
2. **プロトコルスマグリングによる SSRF→RCE（第6章）** — `gopher://` などで生の TCP を内部サービス（Redis 等）に流し込み、コード実行へ持ち込む技術。

この2つに時間を投資することが、「SSRF を知っている」から「SSRF を極めた」への分岐点になる。本書は全10章でこの道のりを段階的に登る。

## 前提と読者像

- 読者は Web の基礎（HTTP、URL、DNS、TCP の概念）を知っている中〜上級者を想定する。
- 攻撃技法の解説は、すべて**「なぜそう動くのか」という仕組みの理解**と**それを踏まえた防御**のために行う。本書は攻撃の実行手順書ではない。
- 手を動かす対象は、必ず自分が所有する、または明示的に許可された環境（PortSwigger の無償ラボ、意図的に脆弱なローカル環境、スコープ内のバグバウンティ対象）に限る。

## 現代の重要な前提：IMDSv2

クラウドメタデータ（第4章）を学ぶ前に、一つだけ現代的な前提を押さえておく。AWS の **IMDSv2** は、トークンを `PUT` リクエストで取得し HTTP ヘッダで送る方式のため、**ヘッダを制御できない通常の SSRF では資格情報を抜けないことが多い**。したがって実務では「まず **IMDSv1 が有効か**を確認し、そのルートを追う価値があるかを判断する」のが定石になる。この前提を最初に知っておくと、第4章の意味が明確になる。

## 攻撃系は英語、基礎・防御は日本語が強い

本ロードマップの資料構成が示す通り、SSRF の攻撃技法の深掘りは圧倒的に英語（PortSwigger、HackTricks、PayloadsAllTheThings、Orange Tsai、Intigriti）が充実している。一方、基礎・防御は日本語資料（IPA、徳丸本、Securify、MDN JP、Zenn）が強い。本書はこの両者を日本語で橋渡しするが、細部は必ず各節の出典（原典）に当たってほしい。
